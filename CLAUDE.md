# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Violin Intonation (рабочее название)

Android-приложение: интонационный тренажёр для скрипки. Экран Live в реальном времени
показывает ноту и попадание в неё — крупно, цветом всего экрана, читается с пюпитра
боковым зрением. Спецификация — единственный источник правды по поведению. Ядро подключено
ниже и загружено всегда; разделы фич лежат в `docs/spec/` — читай нужный перед задачей
(карта — в разделе «Скоуп и карта документов»):

@docs/spec.md

Макеты и токены — в `docs/design/` (хэндофф из Claude Design; финальный Live — вариант 8).
Это веб-прототип: переноси смысл, токены и раскладку, а не HTML-структуру.

## Хэндофф дизайна
- Главный файл — `docs/design/project/Интонация.dc.html`. Пути `untitled/...` в `docs/design/README.md` устарели. `Интонация - прототип.dc.html` — интерактивный прототип, вторичен.
- Секции по `id`: `v1` — все состояния Live, `v1-land` — landscape, `v1-tune` — «Настройка», `v1-stubs` — заглушки, `dev` — таблицы для разработчика, `v2` — не реализуется.
- Точные значения лежат не в разметке, а в JS-массивах в конце файла: `tokens` (цвета), `gradients` (стопы фона), `sizes` (dp/sp, базовый экран 412×892), `anims`. Шрифт макета — Manrope.
- **Хэндофф — источник правды только по визуалу.** Его блок «Логика зон» расходится со спекой (tol 5 вместо 8, near ≤ 2·tol вместо ≤ 20, EMA α 0.18 вместо 0.3, тишина 600 мс вместо 300, шум 2 с + диалог вместо 1 с), а таблица `anims` — по таймингам (кольцо 3000 мс вместо 2 с, кроссфейд 300–350 мс вместо ~150). По поведению и числам домена всегда побеждает `docs/spec.md`.
- Имена файлов с кириллицей на macOS хранятся в NFD: в shell обращайся к ним через glob (`*.dc.html`), а не набранным именем.

## Стек
- Название — Violin Journey, пакет кода и `applicationId` магазинов — `com.violinjourney.app` (до 24.09.2026 был шаблонный `com.example.violintuner`; на телефоне владельца данные живут под ним, пока их не перенесут «Копией данных»). **Debug-сборка — `com.violinjourney.app.debug`**: отдельное приложение рядом с магазинным, его данных не касается. Все `adb`-команды с `run-as` / `pm` / `am start` на эмуляторе — по debug-id, `am start -n com.violinjourney.app.debug/com.violinjourney.app.MainActivity`.
- Release подписывается ключом магазинов (один для RuStore и Google Play): файл и пароли — в `local.properties` (`releaseStoreFile`, `releaseStorePassword`, `releaseKeyAlias`, `releaseKeyPassword`), сам ключ — `~/keys/violin-journey/release.jks`, вне репозитория. Без них release собирается неподписанным. Потеря ключа = невозможность обновлять приложение. Шаги публикации — `docs/release.md`.
- Kotlin, Jetpack Compose + Material 3 (Compose BOM), Gradle Kotlin DSL, version catalog `gradle/libs.versions.toml`
- Hilt, Coroutines/Flow, Navigation Compose
- minSdk 26, Java 17 (`compileOptions`; Gradle-демон работает на JDK 21). Модули: `app` (Android-приложение), `shared` (Kotlin Multiplatform — общий код Android и iOS), `shared-testing` (тестовые сигналы для тестов обоих) — раздел «Общий модуль и iOS»
- DataStore Preferences — пользовательские настройки и идущее занятие (`core/settings`); Room — сессии, занятия, трофеи, репертуар, настройки звука и минусовки (`core/data`, база `violin.db` v13)
- Никаких сторонних DSP-библиотек: детектор высоты тона свой (YIN и MPM), параметры — в спеке

## Архитектура
- Clean + MVI. Пакеты: `feature/live` (закладка и листы подходов — `block`), `feature/onboarding`, `feature/settings`, `feature/session`, `feature/history` (вкладка «Записи»), `feature/practice`, `feature/repertoire` (список, `form`, `piece`, `stand`), `feature/sound` (экран «Звук»), `feature/backup` (копия и восстановление), `feature/journey` (путешествие; открытки — `art`), `feature/home` (дом, лавка, «Обставить», дома; сборка комнаты — `art`), `feature/camera` (своя камера на CameraX — только для видео под минусовку); общее — `core/audio`, `core/domain`, `core/data`, `core/settings`, `core/analytics` (обезличенная статистика, 3.34), `core/recording` (конвейер записи `TakePipeline`), `core/backup` (копия данных), `core/ui` (тема, токены, общие компоненты, форматы, запрос разрешения на микрофон).
- Экран: `LiveContract` (State / Intent / Effect), `LiveViewModel`, `LiveScreen` (stateless: принимает State и `(Intent) -> Unit`), `LiveRoute` (ViewModel + навигация).
- Доменная логика (центы, зоны, сглаживание, гистерезис, снэп к струнам) — чистый Kotlin без Android-зависимостей в `core/domain`, покрыта unit-тестами. Ядро Live (верхний уровень `core/domain`, детекторы `core/audio/dsp`, `FrameAnalyzer`, `DigitalSilenceWatchdog`) лежит в модуле `shared` с теми же пакетами; подпакеты `core/domain` пока в `app`. С шагом 2 там же контракт, редьюсер и экран Live (раздел «Общий модуль и iOS»).
- Все числовые константы — в `IntonationConfig` со значениями из спеки; числа учёта занятий — в `PracticeConfig` (spec 5.6). Магических чисел в коде нет. Эталон A4 и допуск — выбор пользователя: готовый конфиг приходит потоком из `IntonationConfigSource`, синглтон `IntonationConfig` в Hilt — только значения по умолчанию.
- Аудио: интерфейс `PitchSource`; `MicPitchSource` (AudioRecord, фоновый диспетчер) и `FakePitchSource` (превью, тесты, разработка без микрофона). ViewModel не знает про AudioRecord.
- Кольцо, шкала, фоновый градиент — `Canvas` / `Modifier.drawBehind` в Compose, без View-интеропа.

## Compose-правила
- `@Preview` на каждое состояние Live из spec 3.4 плюс режим «Настройка» (авто и зафиксированная струна).
- Цвета зон (inTune / near / off) — семантические токены темы; `colorScheme.error` для «мимо» не использовать.
- Нота — табличные цифры (`TextStyle(fontFeatureSettings = "tnum")`), чтобы ширина не прыгала.
- Live: `FLAG_KEEP_SCREEN_ON`; для landscape отдельная раскладка, а не растянутый портрет.
- Строки UI — только через ресурсы. **Источник текстов — русский, `res/values-ru/`** (`strings.xml`, `strings_home.xml`, сгенерированный `home_catalog.xml`); `res/values/` — английский, запасной для всех языков, на которых приложение не говорит; ещё восемь — `values-de / fr / es / it / pt / ko / zh / ja` (spec 3.26). Слова Live — в `shared/src/commonMain/composeResources/values*/strings_live.xml` (общие с iOS, те же папки языков); там апостроф и кавычки пишутся **без** `\` — Compose-ресурсы не снимают экранирование, и `LocalizationTest` это ловит. Новая строка = русская строка + перевод на все языки по `docs/i18n-glossary.md`, иначе `LocalizationTest` уронит сборку (быстрая проверка без Gradle — `python3 tools/i18n/check.py <тег>`). Переводы машинные, носителями не вычитаны. Код, комментарии, имена — на английском.

- Замер живой картины на открытом экране: `python3 tools/perf/measure.py <подпись> [секунды] [серийный номер]`; попиксельная сверка снимков — `tools/perf/snap.py`. Как поднять эмулятор с настоящей видеокартой и чем выключать запекание и часы картин — `docs/plan-performance.md`.
- Lint: `./gradlew :app:lintDebug`. Инструментальные тесты (нужен девайс/эмулятор): `./gradlew :app:connectedDebugAndroidTest -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true` — тесты Room и кодера звука. **Без этого флага Gradle после прогона удаляет приложение с устройства вместе с данными** (настройки, сессии): верни сборку через `adb install` и предупреди владельца.
- Инструментальные тесты и установку гоняй только на эмуляторе: `ANDROID_SERIAL=emulator-5554 ./gradlew …` — к машине бывает подключён телефон владельца. `adb` не в PATH: `~/Library/Android/sdk/platform-tools/adb`; рабочий AVD — `Pixel_7`. `adb shell input tap` по координатам теряется — находи элемент по тексту через `uiautomator dump`; после `adb install -r` — `am force-stop` + `am start`. Остальные приёмы проверки — в `docs/notes/<фича>.md`.
- Задача готова только когда сборка и unit-тесты (оба модуля) зелёные. Падающий тест чинится через причину, а не через правку теста.

## Общий модуль и iOS
Перенос на iOS идёт через Kotlin Multiplatform в ветке `kmp`; `main` остаётся чистым Android-проектом. Общее почти всё: домен, данные (Room KMP, DataStore), ViewModel'и, экраны и маршруты. На iOS работают онбординг, вкладки «Занятия · Live · Записи», Live с записью дублей, экран записи с плеером и видео, «Звук», дом, путешествие, репертуар (разделы, формы, произведение, пюпитр, видео-дубли из системной камеры и галереи), «Поделиться», копия данных, минусовка, своя камера «Снять под минусовку», статистика AppMetrica. Проверено: симулятор и iPhone владельца (iPhone 15 Pro Max); со скрипкой на iOS пороги не подбирал никто.
- Модули: `shared` (цели `android` через `com.android.kotlin.multiplatform.library`, `iosArm64`, `iosSimulatorArm64`; фреймворк `Shared`), `shared-testing` (`SignalSynth`, фейки — только для тестов). Compose Multiplatform 1.10.2 и material3 1.9.0 дают на Android ровно androidx Compose из BOM — поднимать только вместе, сверяя `:app:dependencies`. JB navigation-compose 2.9.2 — только в `iosMain` (Android остаётся на androidx navigation в `app`).
- В `commonMain` нет `java.*`/`android.*`. Платформенное — через `expect`/`actual`: файл `PlatformFile` (на Android `typealias` на `java.io.File`, поэтому старый код не менялся) и его функции (`fileName`, `sizeBytes`, `deleteFile`, `child`, `listNames`, `moveTo`, `openInput`/`openOutput`…); потоки `ByteInput`/`ByteOutput` (на Android — `InputStream`/`OutputStream`); `IOException` — из okio (на JVM это `java.io.IOException`); блокировка `PlatformLock` + инлайн `withLock`; время — `WallClock` (kotlinx-datetime), вместо `java.time`.
- Hilt не видит `shared`: общие классы без `@Inject`, приложение даёт их через `@Provides` (`SharedModule`, модули фич), а ViewModel'и — `open class` в `shared` и наследники `Hilt<Имя>` с `@HiltViewModel` в `app`; маршруты получают ViewModel параметром, `AppNavHost` передаёт `hiltViewModel<HiltX>()`. На iOS то же собирает руками `IosGraph` (`iosMain/ios`), навигация — `IosNavHost` (те же маршруты), корень — `IosApp`, вход — `MainViewController`.
- Платформенные куски экранов — «системы»: `rememberPieceSystem` (камеры, пикеры, отправка видео), `rememberBackupSystem` (место копии, файл копии, перезапуск), `rememberFileSender`, `rememberMicPermissionRequester`/`Check`, `rememberAnimationsRemoved`, `KeepScreenOn`, `VideoSurface`; тосты — `LocalMessages` (Android — `Toast`, iOS — свой).
- Строки: источник по-прежнему `app/src/main/res/values*/`; задача `:shared:syncComposeStrings` копирует их (с `composeResources/files` — картинками дома и путешествия) в `shared/build/generated/composeStrings`, снимая экранирование Android (`\'`, `\"`, `\?`, `\@`, `%%` — список `androidEscapes` входит в ключ задачи). Общий код берёт строки через `Res.string`; ViewModel'и, которым строка нужна без suspend, на iOS получают тексты, прочитанные при старте (`IosTexts`: `IosScaleTexts`, `IosShareTexts`). Тексты системных запросов iOS (микрофон, камера) — `mic_permission_text`/`camera_permission_text`, `iosApp/iosApp/InfoPlist.xcstrings` пишет `python3 tools/ios/infoplist.py`.

## Языки
- Язык интерфейса — язык устройства или выбранный для приложения в системе (Android 13+: `res/xml/locales_config.xml`, строка «Язык» в «Настройках» открывает системный экран; своего переключателя нет). `Formats.use(locale)` зовут `ViolinTunerApp` (`onCreate`, `onConfigurationChanged`) и `MainActivity.onCreate` — язык, выбранный для одного приложения, доходит только до ресурсов активности.
- `Formats` говорит на языке интерфейса, а не устройства: `FormatLanguage` (чистые данные — локаль, единицы «ч / мин / МБ», единицы экрана «Звук», шаблоны дат, правило множественного числа). **На JVM, в тестах, язык форматов — русский**: все прежние тесты форматов написаны на нём; тест другого языка зовёт `Formats.use(FormatLanguage…)` и возвращает русский в `@After`.
- Формы слов после чисел — `Formats.plural(count, one, few, many)` по трём строкам ресурсов, не ресурс `plurals` (тот следует устройству, а не интерфейсу): русскому нужны все три, остальным — `one` и `many`, корейскому, китайскому и японскому — только `many`; переводчики делают `few` равным `many`.
- Города в трёх массивах (`journey_cities`, `journey_cities_to` — форма после «до / из», …): в каждом языке форма подобрана под его предлог. Предложного падежа («в Вене») в массивах нет — фразы строятся без него.
- Каталог лавки: экспортёр пишет только русский `values-ru/home_catalog.xml`; в остальных языках это переведённая копия с теми же ключами — после перевыгрузки каталога новые ключи надо перевести.

## Процесс
- Крупную задачу начинай с плана: список файлов, что меняется, какие тесты. Код — после подтверждения.
- Один коммит — одна логическая единица: `feat(live): ...`, `fix(audio): ...`, `test(domain): ...`.
- Зависимости и версии в `libs.versions.toml` не добавлять и не менять без явного согласия (CameraX 1.6.2 согласован владельцем 2026-09-23).
- В прод-коде нет `runBlocking`, `GlobalScope`, проглоченных исключений и TODO без пояснения.
- Если спека не отвечает на вопрос — спроси, а не додумывай поведение.
- Сборка для магазина (RuStore, Google Play) — только по порядку `docs/release.md`, раздел «Каждая сборка для магазина»: `versionCode` + 1, проверка обновления поверх предыдущей магазинной сборки. Новая версия базы = `AppDatabase.VERSION` + 1, миграция в `DatabaseMigrations.ALL`, закоммиченная схема (иначе `DatabaseMigrationChainTest` роняет сборку) и тест шага в `DatabaseMigrationTest`.

## Настройки, онбординг, старт приложения
После шести шагов spec §8 добавлены онбординг и минимальные настройки (spec 3.7, 3.8); проверены на эмуляторе на сборке `-PfakePitch=true`, на телефоне — нет.

Детектор тоже создаётся под конфиг — `PitchDetectorFactory`. В тестах — `FakeSettingsRepository`; реализация на DataStore тестируется на JVM на временном файле.

- `navigateToTopLevel` делает `popUpTo(Live)`, а не `findStartDestination()`: при первом запуске стартовая вершина графа — онбординг, которого в стеке уже нет, и вкладки начали бы копиться.
- Проверить первый запуск на эмуляторе: `adb shell pm clear com.violinjourney.app.debug`; координаты и тексты для `input tap` удобно брать из `adb shell uiautomator dump`.

## Раскладки и движение Live
- Раскладку выбирает форма доступной области (`BoxWithConstraints`: шире, чем выше → landscape), а не `Configuration`; только скрытие нижней панели в `MainActivity` смотрит на ориентацию. Landscape — отдельный `LandscapeLayout`, не растянутый портрет.
- Размеры — чистый `LiveLayoutMath` (в dp, с тестами): диаметр кольца = min(макет, свободная ширина, свободная высота − то, что должно остаться под кольцом). Нота масштабируется от кольца и делится на `fontScale` — системный размер шрифта на неё не влияет намеренно.
- Длительности из хэндоффа — в `LiveMotion`; кроссфейд цвета зоны — число спеки, идёт через `LiveState`. Рост кольца не анимируется (следует домену покадрово), анимируется только падение в ноль. Бегунок после тишины `snapTo`, дальше пружина.
- Содержимое кольца меняется `Crossfade` по виду содержимого (`RingContentKind`), а не по ноте: нота обязана меняться мгновенно. Оба слоя `fillMaxSize` — иначе `Crossfade` ставит их от левого верхнего угла и тексты разной ширины встают рядом.
- Проверка раскладок на эмуляторе: поворот — `adb shell settings put system accelerometer_rotation 0` + `user_rotation 1`; маленький экран — `adb shell wm size 720x1280` + `wm density 320`; после проверки вернуть (`accelerometer_rotation 1`, `user_rotation 0`, `wm size reset`, `wm density reset`). `adb shell input tap` сразу после старта приложения теряется — жди ~2 с.

## Аудио и детекторы
- Цепочка: `AudioRecord` → хопы PCM16 по 512 → `FrameAnalyzer` (окно 2048, RMS, детектор, `tMs` по счётчику сэмплов) → `PitchFrame`. Всё, кроме цикла чтения в `MicPitchSource`, — чистый Kotlin в `core/audio` и `core/audio/dsp`, тестируется на JVM синтетикой из `SignalSynth`.
- Оба детектора обязаны проходить `PitchDetectorContractTest` (цели точности из spec 5.1, октавные ловушки G3, шум, вибрато). Новый детектор — новый наследник этого теста.
- Общее для YIN и MPM: `LagSearch` — sinc-интерполяция (Lanczos) функции лага и поиск экстремума золотым сечением. Парабола даёт до 3 центов ошибки в верхней октаве, поэтому её нет. В YIN позиция минимума ищется по ненормированной разностной функции (нормировка смещает минимум), глубина — по нормированной.
- Правило кандидатов (spec 5.1): сначала выбор «первый провал в пределах `octaveDipMargin` от самого глубокого» среди всех провалов, и только потом порог. Обратный порядок даёт уверенные октавные ошибки на шумном тоне — это ловит `DetectorComparisonTest`.
- По умолчанию — MPM (биндинг в `AudioModule`): на синтетике точность равна YIN (≤ 0.5 цента до G6, ≤ 1.1 в верхней октаве), под шумом ошибка чуть меньше (2.1 против 2.3 цента при SNR 10 дБ), цена 0.36 против 0.30 мс на кадр на JVM. Разница мала; переключение — одна строка. Детекторы хранят буферы: один экземпляр на аудиопоток, поэтому `MicPitchSource` берёт `Provider<PitchDetector>`.
- Оба детектора отвергают тон при SNR ниже ~7 дБ из-за `clarityThreshold` 0.85 — это свойство порога, а не детектора.
- `PitchSource.requiresMicPermission`: `LiveViewModel` не собирает такой источник, пока маршрут не сообщил о разрешении (`MicPermissionChanged` приходит на каждый `ON_RESUME`); до первого сообщения показывается `Silence`, а не запрос — чтобы он не мигал у тех, кто уже разрешил. `MicUnavailableException` превращается в состояние `MicUnavailable` с повтором через 3 с; любое другое исключение источника роняет приложение намеренно.
- Отладка на живом звуке: debug-сборка раз в секунду пишет в logcat сводку кадров (`adb logcat -s MicPitchSource`): число уверенных кадров, пик RMS в dBFS, пик clarity, гистограмма нот. `peakRms=-Infinity` — вход отдаёт точные нули, это не тишина в комнате, а отвалившийся вход; через `digitalSilenceTimeoutMs` `DigitalSilenceWatchdog` превращает это в `MicUnavailable`, и запись переоткрывается.
- Если владелец говорит «микрофон отваливается»: `adb logcat -d -s MicPitchSource:W` — строки `input is digitally silent, reopening` раз в ~5 с значат, что вход отдаёт точные нули (мост эмулятора), а не что сломан код. После сбоя `LiveViewModel` держит `MicUnavailable`, пока не придёт кадр с `rms > 0` (`awaitingSignal`), иначе экран мигал бы между двумя надписями на каждой попытке. При `hostmicoff` эмулятор отдаёт не нули, а слабый шум («Играйте…»); нули — переходные моменты и зависший мост.
- Микрофон эмулятора ненадёжен: передачу с хоста надо включать (`adb emu avd hostmicon` или Extended controls → Microphone), настройка сбрасывается, мост временами отдаёт нули или мусор, вход сильно перегружен (пики −1 dBFS). Если «приложение не слышит» на эмуляторе — сначала смотри сводку кадров в logcat, а не в код. Пороги подбирать только на телефоне.
- Проверка записи без инструмента: `adb shell dumpsys audio | grep violintuner` — видны `rec update` при открытом экране и `rec stop` через ~2 с после ухода в фон.

## Экран Live
- `LiveViewModel`: один коллектор `frames → engine → LiveSignal`, режим читается на каждом кадре (движок однопоточный), `conflate()` после движка, `stateIn(WhileSubscribed)` — источник останавливается, когда экран не виден. Диспетчер внедряется через `@DefaultDispatcher`.
- Числа из спеки попадают в UI только через `LiveState` (`scale`, `zoneCrossfadeMs`) — экран не знает про `IntonationConfig`. Размеры из хэндоффа — в `LiveDimens`; позиции на шкале — чистый `ScaleMath` (с зажимом: в «Настройке» центы бывают ±700).
- С spec 3.27 за Live — картина места (комната или зал со сцены), свет гаснет, пока звучит нота; непрозрачный градиент зоны остался только в сборке `-PplainLive=true`. Как это устроено — `docs/notes/venue.md`.
- Градиент, статус, заливка кольца и ореол бегунка берут один анимированный `zoneColor` (spec 3.4). «Нет градиента» — это `noneGradient` со стопами, равными `surface`, поэтому кроссфейд одинаков для всех переходов. Центр градиента привязан к реальному центру кольца и читается в фазе отрисовки.
- TooNoisy — текст в кольце по спеке; модальный диалог из хэндоффа отвергнут (противоречит принципу «без касаний»). Ореол бегунка в v1 фиксированной ширины: «ореол вибрато» из хэндоффа — v2. Диез — «#»: в Manrope нет глифа ♯.
- Тесты с `FakePitchSource` обязаны передавать `timeSource = testTimeSource`, иначе поток идёт по реальным часам и виртуальное время `runTest` с ним расходится.
- Проверка глазами: `adb install` debug-сборки на эмулятор и `adb exec-out screencap -p`; фазы DEMO привязаны к реальному времени от старта (0–4 с в строе, 4–8 выше, 8–12 ниже, 12–16 вибрато, 16–20 тишина, 20–24 шум).

## Конвейер домена
`PitchFrame` → `IntonationEngine.process(frame, TargetMode)` → `IntonationReading` (`Silence` / `TooNoisy` / `Active`). Движок — единственная точка сборки; остальные классы `core/domain` — его детали, у каждого свой тест.
- Время берётся только из `PitchFrame.tMs`: в домене нет часов и корутин, тесты подают кадры с шагом 10 мс (`TestFrames`). Движок не потокобезопасен — один коллектор.
- Движок считает всё от `freqHz`; поля `cents` / `midi` кадра он не читает (они для записи и отладки), в режиме «Настройка» центы считаются от струны.
- Порядок внутри: `SignalGate` (тишина / шум / провал) → кандидат ноты из сырого питча → `NoteLock` (100 мс) → `PitchSmoother` по дробному MIDI → `ZoneHysteresis` → `HoldTimer`.
- Два сглаживателя: кадры зафиксированной ноты идут в основной, кадры ещё не зафиксированного кандидата — в «ожидающий», который при фиксации становится основным. Поэтому новая нота стартует без «переезда» со старой, а одиночная октавная ошибка вообще не попадает в показание.
- Кадр чужого кандидата для текущей ноты равносилен провалу питча (`bridgeGap`): показание замирает, через `pitchGapToleranceMs` кольцо сбрасывается.
- Смена `TargetMode` (в том числе фиксация струны) полностью сбрасывает движок.
- `FakePitchSource.frameAt(index)` детерминирован и работает без корутин — используй его в `@Preview` и сценарных тестах. Параметры сценариев — в самом фейке, не в `IntonationConfig`.
- Известное свойство чисел из спеки: медиана 5 + EMA 0.3 ослабляют вибрато 5.5 Гц лишь до ~0.65 амплитуды, так что вибрато глубже ±14 центов вокруг ноля мигает в янтарный. «Режим вибрато» — v2; не «чини» это подкруткой констант без согласования.

## Что неочевидно в коде
- Токены зон и стили ноты не входят в Material-схему: бери их из `ViolinTheme.zoneColors` и `ViolinTheme.liveTypography` (CompositionLocal), стопы фонового градиента — `ZoneGradient.colorStops`. Сырые цвета в `Color.kt` — `internal`, напрямую из UI не использовать. Общая с iOS часть темы — в `shared`: `BasePalette.kt` (база палитры и `ViolinColorScheme`; публичная только потому, что из неё строятся цвета остальных экранов приложения), `LivePalette.kt` (цвета Live, `internal`), `ViolinBaseTheme(fontFamily)`; `ViolinTheme` приложения оборачивает её. Код в `shared` берёт токены через `LiveTheme`, а не `ViolinTheme`.
- Manrope — один вариативный TTF (`res/font/manrope_variable.ttf`), веса задаются через `FontVariation` (experimental API, opt-in локализован в `Type.kt`). Лицензия — `docs/licenses/Manrope-OFL.txt`. Для iOS тот же файл лежит в `shared/src/iosMain/composeResources/font/`.
- Маршруты навигации — строки из `TopLevelDestination`; type-safe routes потребовали бы плагин kotlinx.serialization, то есть новую зависимость.
- compileSdk 37 при targetSdk 36 — так задумано: этого требуют `core-ktx` и `lifecycle` из каталога версий, поведение рантайма не меняется.
- Макеты заглушек (`v1-stubs`) в хэндоффе нарисованы в половинном масштабе (206×446) — размеры оттуда умножай на 2.
