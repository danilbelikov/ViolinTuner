# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Violin Intonation (рабочее название)

Android-приложение: интонационный тренажёр для скрипки. Экран Live в реальном времени
показывает ноту и попадание в неё — крупно, цветом всего экрана, читается с пюпитра
боковым зрением. Спецификация — единственный источник правды по поведению, читай её
перед любой задачей:

@docs/spec.md

Макеты и токены — в `docs/design/` (хэндофф из Claude Design; финальный Live — вариант 8).
Это веб-прототип: переноси смысл, токены и раскладку, а не HTML-структуру.

## Хэндофф дизайна
- Главный файл — `docs/design/project/Интонация.dc.html`. Пути `untitled/...` в `docs/design/README.md` устарели. `Интонация - прототип.dc.html` — интерактивный прототип, вторичен.
- Секции по `id`: `v1` — все состояния Live, `v1-land` — landscape, `v1-tune` — «Настройка», `v1-stubs` — заглушки, `dev` — таблицы для разработчика, `v2` — не реализуется.
- Точные значения лежат не в разметке, а в JS-массивах в конце файла: `tokens` (цвета), `gradients` (стопы фона), `sizes` (dp/sp, базовый экран 412×892), `anims`. Шрифт макета — Manrope.
- **Хэндофф — источник правды только по визуалу.** Его блок «Логика зон» расходится со спекой (tol 5 вместо 8, near ≤ 2·tol вместо ≤ 20, EMA α 0.18 вместо 0.3, тишина 600 мс вместо 300, шум 2 с + диалог вместо 1 с), а таблица `anims` — по таймингам (кольцо 3000 мс вместо 2 с, кроссфейд 300–350 мс вместо ~150). По поведению и числам домена всегда побеждает `docs/spec.md`.
- Имена файлов с кириллицей на macOS хранятся в NFD: в shell обращайся к ним через glob (`*.dc.html`), а не набранным именем.

## Стек
- Kotlin, Jetpack Compose + Material 3 (Compose BOM), Gradle Kotlin DSL, version catalog `gradle/libs.versions.toml`
- Hilt, Coroutines/Flow, Navigation Compose
- minSdk 26, Java 17 (`compileOptions`; Gradle-демон работает на JDK 21), один модуль `app`
- DataStore Preferences — пользовательские настройки и идущее занятие (`core/settings`); Room — сессии, занятия, трофеи и репертуар (`core/data`, база `violin.db` v4)
- Никаких сторонних DSP-библиотек: детектор высоты тона свой (YIN и MPM), параметры — в спеке

## Архитектура
- Clean + MVI. Пакеты: `feature/live`, `feature/onboarding`, `feature/settings`, `feature/session`, `feature/history` (вкладка «Записи»), `feature/practice`, `feature/repertoire` (список, `form`, `piece`, `stand`); общее — `core/audio`, `core/domain`, `core/data`, `core/settings`, `core/recording` (конвейер записи `TakePipeline`), `core/ui` (тема, токены, общие компоненты, форматы, запрос разрешения на микрофон).
- Экран: `LiveContract` (State / Intent / Effect), `LiveViewModel`, `LiveScreen` (stateless: принимает State и `(Intent) -> Unit`), `LiveRoute` (ViewModel + навигация).
- Доменная логика (центы, зоны, сглаживание, гистерезис, снэп к струнам) — чистый Kotlin без Android-зависимостей в `core/domain`, покрыта unit-тестами.
- Все числовые константы — в `IntonationConfig` со значениями из спеки; числа учёта занятий — в `PracticeConfig` (spec 5.6). Магических чисел в коде нет. Эталон A4 и допуск — выбор пользователя: готовый конфиг приходит потоком из `IntonationConfigSource`, синглтон `IntonationConfig` в Hilt — только значения по умолчанию.
- Аудио: интерфейс `PitchSource`; `MicPitchSource` (AudioRecord, фоновый диспетчер) и `FakePitchSource` (превью, тесты, разработка без микрофона). ViewModel не знает про AudioRecord.
- Кольцо, шкала, фоновый градиент — `Canvas` / `Modifier.drawBehind` в Compose, без View-интеропа.

## Compose-правила
- `@Preview` на каждое состояние Live из spec 3.4 плюс режим «Настройка» (авто и зафиксированная струна).
- Цвета зон (inTune / near / off) — семантические токены темы; `colorScheme.error` для «мимо» не использовать.
- Нота — табличные цифры (`TextStyle(fontFeatureSettings = "tnum")`), чтобы ширина не прыгала.
- Live: `FLAG_KEEP_SCREEN_ON`; для landscape отдельная раскладка, а не растянутый портрет.
- Строки UI — только через `strings.xml`, язык по умолчанию русский. Код, комментарии, имена — на английском.

## Команды
- Сборка: `./gradlew :app:assembleDebug`
- Unit-тесты: `./gradlew :app:testDebugUnitTest`
- Один класс / один тест: `./gradlew :app:testDebugUnitTest --tests "*.ZoneClassifierTest"` / `--tests "*.ZoneClassifierTest.methodName"`
- Сборка на фейковом источнике вместо микрофона (эмулятор, проверка всех состояний без инструмента): `./gradlew :app:assembleDebug -PfakePitch=true`
- Отчёт сравнения детекторов: `./gradlew :app:testDebugUnitTest --tests "*.DetectorComparisonTest"`, таблица — в `<system-out>` файла `app/build/test-results/testDebugUnitTest/TEST-*DetectorComparisonTest.xml`
- Lint: `./gradlew :app:lintDebug`. Инструментальные тесты (нужен девайс/эмулятор): `./gradlew :app:connectedDebugAndroidTest -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true` — тесты Room и кодера звука. **Без этого флага Gradle после прогона удаляет приложение с устройства вместе с данными** (настройки, сессии): верни сборку через `adb install` и предупреди владельца.
- Задача готова только когда обе команды зелёные. Падающий тест чинится через причину, а не через правку теста.

## Процесс
- Крупную задачу начинай с плана: список файлов, что меняется, какие тесты. Код — после подтверждения.
- Один коммит — одна логическая единица: `feat(live): ...`, `fix(audio): ...`, `test(domain): ...`.
- Зависимости и версии в `libs.versions.toml` не добавлять и не менять без явного согласия.
- В прод-коде нет `runBlocking`, `GlobalScope`, проглоченных исключений и TODO без пояснения.
- Если спека не отвечает на вопрос — спроси, а не додумывай поведение.

## Сессии: запись, анализ, история
Идёт по этапам 7–11 (spec §8, `docs/plan-history.md`). **Сделаны все этапы 7–11.** Не проверено никем: запись звука с живого микрофона и синхронность курсора на слух — на эмуляторе проверены кодер (инструментальный тест) и плеер на подложенной сессии.
- Звук: `PitchSource.audioTap` (у фейка null). `MicPitchSource` отдаёт каждый хоп в `HopAudioTap` (чистый Kotlin, тесты); запись звука начинается со следующего хопа и знает `startTMs` по тому же счётчику сэмплов, что и кадры. `LiveViewModel` запускает `SessionRecorder` с кадра `tMs >= startTMs`, поэтому сдвиг не хранится и схема базы не менялась. Сессия хранит имя файла, не путь (`SessionAudioFiles`, `files/sessions/<uuid>.m4a`).
- `AacFileEncoder`: `MediaCodec` AAC-LC 64 кбит/с + `MediaMuxer`, свой поток за ограниченной очередью — цикл микрофона кодек не ждёт. Переполнение очереди, ошибка кодека, недописанный файл → сессия сохраняется без звука, показания не теряются. Кодек конфигурируется с `CONFIGURE_FLAG_ENCODE` — без него `configure` падает, и это видно только на устройстве: всё, что трогает `MediaCodec`, проверяй инструментальным тестом (`AacFileEncoderTest`).
- Плеер: `SessionPlayer` (интерфейс) / `MediaPlayerSessionPlayer`; `SessionViewModel` создаёт его только если файл существует, освобождает перед удалением и в `onCleared`, ставит на паузу по `ON_STOP`. Курсор на ленте — `PianoRollMath.scrollToFollow`; прокрутка за курсором идёт в `LaunchedEffect`, не в композиции.
- Удаление сессии удаляет файл (сначала строка, потом файл); файлы без сессии чистятся при старте (`AppStartViewModel` → `deleteOrphanAudio`), кроме тех, что моложе `maxSessionMs` — это может быть идущая запись.
- Инструментальные тесты без потери данных на устройстве: `./gradlew :app:connectedDebugAndroidTest -Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true`. Проверить плеер без звука в микрофон: `afconvert -f m4af -d aac` → положить файл в `files/sessions/` через `run-as`, вставить строку сессии с `audioPath`; громкость эмулятора на время проверки — `adb shell cmd media_session volume --stream 3 --set 0`, потом вернуть.
- «История»: `HistoryReducer` (чистый, «сегодня» и пояс приходят снаружи из `Clock`) делает из сводок недели, дельту, фильтр и карточки; график — `WeeklyChart` на `Canvas`, геометрия в `WeeklyChartMath`. Счётчик и график от фильтра не зависят. Формы «N сессий» — `Formats.pluralRu`, не ресурс `plurals` (он следует языку устройства).
- Наполнить «Историю» на эмуляторе старыми неделями: вытащить `violin.db`, вставить строки питоном (копия существующей сессии со сдвинутым `startedAtEpochMs` + её строка в `session_samples`), `wal_checkpoint(truncate)`, залить обратно через `run-as … sh -c 'cat > databases/violin.db'` при остановленном приложении и удалить `-wal` / `-shm`.
- Экран сессии: `SessionContentMapper` (чистый, с тестами) превращает `SessionDetails` в `SessionContent` — сырые числа и зоны; форматирует их экран через `core/ui/format/Formats` (локаль зафиксирована на `ru`, минус — U+2212, десятичная запятая). Цвета считаются с допуском самой сессии.
- Лента нот: геометрия — чистый `PianoRollMath` в dp (масштаб, диапазон прокрутки, метки времени, контур, hit test, всё с тестами); рисуется в холст размером с окно с собственным смещением прокрутки (`Modifier.scrollable`), потому что один широкий холст на час записи превышает допустимый размер раскладки. Подписи нот слева неподвижны, текст меряется с `softWrap = false`, иначе метка у правого края переносится.
- Маршрут `session/{sessionId}` — поверх вкладок; нижняя панель скрывается сама, потому что он не вкладка. Удаление сессии закрывает экран через `SessionEffect.Close`.
- Отдельные ноты ленты недоступны для TalkBack — у холста одно общее описание; это известное ограничение.
- Запись: кнопка лишь меняет желание `recordingRequested`; `SessionRecorder` живёт внутри `pipeline(config)` рядом с движком, на его потоке, и следует желанию покадрово — второго коллектора и межпоточного доступа нет. Остановка играющим → сохранить и `LiveEffect.OpenSession` (или `ShowNoNotesRecorded`); конец по любой другой причине (уход с Live, смена настроек, отзыв разрешения, сбой микрофона) → тихое сохранение в `onCompletion` под `NonCancellable`. `onCompletion` стоит **до** `retryWhen`, иначе сбой микрофона терял бы запись.
- Поворот запись не рвёт: это те же 2 с `WhileSubscribed`. Во время записи режим не переключается; в «Настройке», без разрешения и при `MicUnavailable` запись не начинается (`LiveReducer.canRecord`).
- Отрезок мини-ленты — нота в одной зоне; бары кешируются в рекордере и пересчитываются только при закрытии корзины (20 Гц), а не на каждом кадре.
- Посмотреть базу на эмуляторе: `sqlite3` на образе нет — вытащи `databases/violin.db*` через `adb exec-out run-as com.example.violintuner cat …` и открой на хосте питоном.
- `core/domain/session` — чистый Kotlin: `SessionSampler` (показания движка → корзины 50 мс по `tMs`), `SessionAnalyzer` (сегменты, балл, доли зон, средняя ошибка, смещение, проблемные ноты, «По струнам», зоны для мини-столбиков), `StringFinger` (эвристика первой позиции — неточна в позициях намеренно, spec 5.5), `SampleCodec` (3 байта на корзину), `HistoryWeeks` (недели с понедельника, зависят от пояса смотрящего).
- В запись идут только свежие измерения: показание, которое движок держит на экране через провал питча, помечено `IntonationReading.Active.held` и сэмплером пропускается. Экран на `held` не смотрит.
- Балл считается по самим отклонениям, без гистерезиса зон; граница «рядом» — `nearCents` (20), а не 2·допуск из прототипа.
- `core/data/session` — Room (`violin.db`, схема в `app/schemas`, её коммитим). Две таблицы: сводка и блоб отсчётов. Сегменты не хранятся: `RoomSessionRepository.details` выводит их заново с допуском и размером корзины самой сессии (`forSession`). Зоны мини-столбиков хранятся буквами, не ordinal.
- Unit-тесты покрывают домен и маппер; DAO и репозиторий — инструментальный `RoomSessionRepositoryTest` (в androidTest `runBlocking` допустим: это тестовый код без виртуального времени).

- Связь с Live: `LiveState.practiceMs` берётся из общего `RunningPracticeStore.elapsedTicker(clock)` (`core/domain/practice/RunningPracticeTicker.kt`, им же живёт таймер на «Занятиях»). Чип — `PracticeChipSlot` (портрет: под переключателем; landscape: первым в правой колонке), тап → `LiveEffect.OpenPractice` → `navigateToTopLevel(PRACTICE)`. Отметка звука — `markSoundIfDue` в `map` конвейера: только `IntonationReading.Active` без `held`, только при идущем занятии (его начало зеркалится в `@Volatile practiceStartedAt`), не чаще `soundMarkIntervalMs`; новое занятие обнуляет счётчик.
- Из-за чипа landscape в «Настройке» перестал вмещать слово статуса: `LandscapeSpacing` 12 → 8 dp, а слово при высоте строки < 48 dp уменьшается до 24 sp (`LandscapeStatusCompactHeight`).
- Забытое занятие живёт в `AppStartViewModel` (проверка при каждом `ON_START` активности из `MainActivity`, `PracticePromptHost` поверх вкладок): `ForgottenPractice.check` → `PracticePrompt.Forgotten` (диалог) или `PracticePrompt.Summary` (лист итога — при истёкших 12 ч или по «Изменить время» из диалога без звука). Пока промпт открыт, повторный `ON_START` (поворот) его не пересчитывает — иначе лист превращался бы обратно в диалог. Истёкшее занятие остаётся в DataStore, пока лист не отвечен: смерть процесса между ними ничего не теряет, а чип на Live продолжает тикать — это принято.
- «Закончить в 18:42» берёт время из самого диалога, а не из хранилища: под диалогом Live продолжает слушать, и фейковый источник (или живая скрипка) сдвигает отметку звука уже после показа. На эмуляторе это дало сохранение до «сейчас» вместо 18:42 — есть регрессионный тест. «Продолжаю заниматься» и закрытие диалога тапом мимо ставят отметку звука «сейчас»: считается признаком жизни, вопрос вернётся через час тишины.
- Завершение занятия — только через `PracticeFinisher.save(startedAt, durationMs)` / `discard()` (экран «Занятия» и промпт): `save` сверяет начало с хранилищем, поэтому два ответа на одно занятие не сохранят его дважды.
- Подложить состояние для проверки диалога на эмуляторе (root недоступен, часы не перевести): вытащить `files/datastore/user_settings.preferences_pb` через `run-as`, переписать protobuf питоном (map entry: поле 1 → {1: ключ, 2: Value; long — поле 4}, ключи `practice_started_at`, `practice_last_sound_at`) и залить обратно при остановленном приложении. С фейковым источником Live «звучит» всегда: вариант «без звука» на эмуляторе после открытия Live не воспроизвести, он покрыт unit-тестами.

## Раскладки и движение Live
- Раскладку выбирает форма доступной области (`BoxWithConstraints`: шире, чем выше → landscape), а не `Configuration`; только скрытие нижней панели в `MainActivity` смотрит на ориентацию. Landscape — отдельный `LandscapeLayout`, не растянутый портрет.
- Размеры — чистый `LiveLayoutMath` (в dp, с тестами): диаметр кольца = min(макет, свободная ширина, свободная высота − то, что должно остаться под кольцом). Нота масштабируется от кольца и делится на `fontScale` — системный размер шрифта на неё не влияет намеренно.
- Длительности из хэндоффа — в `LiveMotion`; кроссфейд цвета зоны — число спеки, идёт через `LiveState`. Рост кольца не анимируется (следует домену покадрово), анимируется только падение в ноль. Бегунок после тишины `snapTo`, дальше пружина.
- Содержимое кольца меняется `Crossfade` по виду содержимого (`RingContentKind`), а не по ноте: нота обязана меняться мгновенно. Оба слоя `fillMaxSize` — иначе `Crossfade` ставит их от левого верхнего угла и тексты разной ширины встают рядом.
- Проверка раскладок на эмуляторе: поворот — `adb shell settings put system accelerometer_rotation 0` + `user_rotation 1`; маленький экран — `adb shell wm size 720x1280` + `wm density 320`; после проверки вернуть (`accelerometer_rotation 1`, `user_rotation 0`, `wm size reset`, `wm density reset`). `adb shell input tap` сразу после старта приложения теряется — жди ~2 с.

## Аудио и детекторы
- Цепочка: `AudioRecord` → хопы PCM16 по 512 → `FrameAnalyzer` (окно 2048, RMS, детектор, `tMs` по счётчику сэмплов) → `PitchFrame`. Всё, кроме цикла чтения в `MicPitchSource`, — чистый Kotlin в `core/audio` и `core/audio/dsp`, тестируется на JVM синтетикой из `SignalSynth`.
- Оба детектора обязаны проходить `PitchDetectorContractTest` (цели точности из spec 5.1, октавные ловушки G3, шум, вибрато). Новый детектор — новый наследник этого теста.
- Общее для YIN и MPM: `LagSearch` — sinc-интерполяция (Lanczos) функции лага и поиск экстремума золотым сечением. Парабола даёт до 3 центов ошибки в верхней октаве, поэтому её нет. В YIN позиция минимума ищется по ненормированной разностной функции (нормировка смещает минимум), глубина — по нормированной.
- Правило кандидатов (spec 5.1): сначала выбор «первый провал в пределах `octaveDipMargin` от самого глубокого» среди всех провалов, и только потом порог. Обратный порядок даёт уверенные октавные ошибки на шумном тоне — это ловит `DetectorComparisonTest`.
- По умолчанию — MPM (биндинг в `AudioModule`): на синтетике точность равна YIN (≤ 0.5 цента до G6, ≤ 1.1 в верхней октаве), под шумом ошибка чуть меньше (2.1 против 2.3 цента при SNR 10 дБ), цена 0.36 против 0.30 мс на кадр на JVM. Разница мала; переключение — одна строка. Детекторы хранят буферы: один экземпляр на аудиопоток, поэтому `MicPitchSource` берёт `Provider<PitchDetector>`.
- Оба детектора отвергают тон при SNR ниже ~7 дБ из-за `clarityThreshold` 0.85 — это свойство порога, а не детектора.
- `PitchSource.requiresMicPermission`: `LiveViewModel` не собирает такой источник, пока маршрут не сообщил о разрешении (`MicPermissionChanged` приходит на каждый `ON_RESUME`); до первого сообщения показывается `Silence`, а не запрос — чтобы он не мигал у тех, кто уже разрешил. `MicUnavailableException` превращается в состояние `MicUnavailable` с повтором через 3 с; любое другое исключение источника роняет приложение намеренно.
- Отладка на живом звуке: debug-сборка раз в секунду пишет в logcat сводку кадров (`adb logcat -s MicPitchSource`): число уверенных кадров, пик RMS в dBFS, пик clarity, гистограмма нот. `peakRms=-Infinity` — вход отдаёт точные нули, это не тишина в комнате, а отвалившийся вход; через `digitalSilenceTimeoutMs` `DigitalSilenceWatchdog` превращает это в `MicUnavailable`, и запись переоткрывается.
- Если владелец говорит «микрофон отваливается»: `adb logcat -d -s MicPitchSource:W` — строки `input is digitally silent, reopening` раз в ~5 с значат, что вход отдаёт точные нули (мост эмулятора), а не что сломан код. После сбоя `LiveViewModel` держит `MicUnavailable`, пока не придёт кадр с `rms > 0` (`awaitingSignal`), иначе экран мигал бы между двумя надписями на каждой попытке. При `hostmicoff` эмулятор отдаёт не нули, а слабый шум («Играйте…»); нули — переходные моменты и зависший мост.
- Микрофон эмулятора ненадёжен: передачу с хоста надо включать (`adb emu avd hostmicon` или Extended controls → Microphone), настройка сбрасывается, мост временами отдаёт нули или мусор, вход сильно перегружен (пики −1 dBFS). Если «приложение не слышит» на эмуляторе — сначала смотри сводку кадров в logcat, а не в код. Пороги подбирать только на телефоне.
- Проверка записи без инструмента: `adb shell dumpsys audio | grep violintuner` — видны `rec update` при открытом экране и `rec stop` через ~2 с после ухода в фон.

## Экран Live
- `LiveViewModel`: один коллектор `frames → engine → LiveSignal`, режим читается на каждом кадре (движок однопоточный), `conflate()` после движка, `stateIn(WhileSubscribed)` — источник останавливается, когда экран не виден. Диспетчер внедряется через `@DefaultDispatcher`.
- Числа из спеки попадают в UI только через `LiveState` (`scale`, `zoneCrossfadeMs`) — экран не знает про `IntonationConfig`. Размеры из хэндоффа — в `LiveDimens`; позиции на шкале — чистый `ScaleMath` (с зажимом: в «Настройке» центы бывают ±700).
- Градиент, статус, заливка кольца и ореол бегунка берут один анимированный `zoneColor` (spec 3.4). «Нет градиента» — это `noneGradient` со стопами, равными `surface`, поэтому кроссфейд одинаков для всех переходов. Центр градиента привязан к реальному центру кольца и читается в фазе отрисовки.
- TooNoisy — текст в кольце по спеке; модальный диалог из хэндоффа отвергнут (противоречит принципу «без касаний»). Ореол бегунка в v1 фиксированной ширины: «ореол вибрато» из хэндоффа — v2. Диез — «#»: в Manrope нет глифа ♯.
- Тесты с `FakePitchSource` обязаны передавать `timeSource = testTimeSource`, иначе поток идёт по реальным часам и виртуальное время `runTest` с ним расходится.
- Проверка глазами: `adb install` debug-сборки на эмулятор и `adb exec-out screencap -p`; фазы DEMO привязаны к реальному времени от старта (0–4 с в строе, 4–8 выше, 8–12 ниже, 12–16 вибрато, 16–20 тишина, 20–24 шум).

Уступает движению полосы (`filled.isRunning`): не стартует, бросает начатый проход, следующий — через `AFTER_GROWTH_MS`. Скриншотом блик почти не поймать (проход 1.2 с из 4): снимай `adb shell screenrecord --time-limit 9`, кадры доставай Swift-скриптом на `AVAssetImageGenerator` (ffmpeg на машине нет) и сравнивай строку полосы с кадром покоя.
- `RunningDot(elapsedMs, …)`: дыхание — `rememberInfiniteTransition` (цель постоянна, это можно), дуга — угол от секунд таймера, между тиками доводится кадровым циклом; всё читается в `drawBehind`. Кадры идут только пока занятие идёт и экран в композиции.
- `rolledValue(target, scope, …)`: первое значение берётся как есть, новый `scope` (месяц календаря, конец загрузки) начинает заново — поэтому загрузка, возврат на вкладку и смена месяца числа не гоняют. Читает значение в композиции — карточка перекомпоновывается 600 мс на перемену, это принято.
- Скрипты правок Kotlin лежат вне репозитория; если понадобится перегенерировать иконки — разобрать `const ICONS = [` в `Иконки и жизнь.dc.html` (имя → `UPPER_SNAKE`, у вкладок `sel: fill / inv` → `Selected.FILL / CUT`).

## Live 2: свечение, цифры, строка состояния
Этапы 18–20 сделаны (домен и состояние; светящееся кольцо вместо дуги удержания; строка состояния над кольцом, цифры у слова статуса, шкала только в «Настройке») — план и отклонения в `docs/plan-live2.md`. - Раскладка: `StatusLineRow` (строка состояния; при `statusLine == null` гаснет, показывая последнее, и держит высоту) стоит под переключателем / чипом / рядом струн; в «Настройке» она же подсказка — `StringRow` подсказку больше не рисует. `StatusRow` — слово цветом зоны + серые цифры `displayCents` (`Formats.signedCents`), ширина под «−00» зарезервирована измерением текста. `ScaleSlot` показывает шкалу только в `TUNING`. В кольце без ноты пусто (`RingContentKind.EMPTY`), фразы ушли в строку состояния; `NO_MIC` — как раньше.
- Компактный статус (24 / 30 sp) включается по факту: портретное кольцо < `CompactStatusBelowRing` или строка статуса в landscape ниже `LandscapeStatusCompactHeight`. Дизайн-диаметры: портрет 300, «Настройка» 260, landscape 260 при панели 400 / 892 — ореол (1.456 R) помещается в панель; реальный диаметр по-прежнему считает `LiveLayoutMath` от свободного места.
- **Анимация, цель которой меняется чаще кадров, не должна перезапускаться.** `LaunchedEffect(target) { animatable.animateTo(target) }` при цели, меняющейся каждый кадр, стоит на месте: первый кадр любой анимации Compose ничего не двигает. Так годами «лип» бегунок шкалы (при «+19» стоял на «+5», догонял в паузах). И свечение (`GlowMath.follow`), и бегунок (`MarkerSpring`) шагают по кадрам в одном долгоживущем `LaunchedEffect` с `withFrameMillis`, цель читают через `rememberUpdatedState`, значение отдают в `drawBehind`, а в покое спят на `snapshotFlow`.
- Кольцо — `GlowRing` (`feature/live/components`), вся геометрия и силы — чистый `GlowMath` (доли радиуса контура, стопы ореолов, цвет и непрозрачность контура, волна; с тестами), длительности — `LiveMotion`. Всё, что меняется много раз в секунду (`glow`, `level`, цвет зоны, волны), читается в `drawBehind`: кольцо перерисовывается, а не перекомпоновывается. Ореол выходит за границы компонента на `GlowMath.EXTENT` (1.456 R) и не клипуется намеренно.
- `glow` следует за целью экспоненциально по кадрам (`GlowMath.follow`), а не твином: цель меняется на каждом кадре (растёт с удержанием), перезапускаемый твин с медленным началом стоял бы на месте. Не заменяй на `animateFloatAsState`. Когда цель достигнута, цикл спит на `snapshotFlow` — кольцо в покое кадров не тратит. Первое значение берётся как есть: после поворота и возврата на вкладку свечение не «взбирается» с нуля.
- Волны: `LaunchedEffect(noteSerial)` и `LaunchedEffect(holdComplete)`, частоту держит `WaveGate` (600 мс); волна «новая нота» выключается константой `LiveMotion.NEW_NOTE_WAVE`. В тишине экран держит последний `noteSerial`, иначе уход в тишину считался бы новой нотой.
- Светящийся диск внутри кольца — как в кадрах хэндоффа, вопреки его таблице `layers` («внутри прозрачно»); выключается `GlowMath.DISC_ALPHA = 0`.
- «Убрать анимации»: `LiveRoute` читает `Settings.Global.ANIMATOR_DURATION_SCALE` на каждом `ON_RESUME` и передаёт `reduceMotion` экрану; тогда цель — `LiveState.glowStep`, волн и дыхания нет. Проверка: `adb shell settings put global animator_duration_scale 0` (потом вернуть 1).
- Токены точки состояния — `ViolinTheme.statusColors` (`ready` / `blocked`), не цвета зон; `ringTrack` и `RING_RESET_MS` ушли вместе с дугой. `HoldTimer` и `holdProgress` в домене остались: удержание теперь кормит свечение.
- `LiveReadout` (`feature/live`, чистый) стоит в `pipeline(config)` рядом с движком, на его потоке, время — только `PitchFrame.tMs`: показание движка + кадр → `LiveSignal`. Добавляет `level` (`LoudnessMeter`), `displayCents` (`CentsReadout`) и `noteSerial`. Новый конфиг = новый экземпляр; `reset()` зовётся вместе с `engine.reset()`.
- `LoudnessMeter` (`core/domain`): RMS → dBFS → 0…1 от `silenceRmsDbfs` до `levelCeilingDbfs`, однополюсное сглаживание с разными постоянными времени (атака 50 мс, спад 300 мс) по разнице `tMs` — не зависит от частоты кадров. Точные нули RMS — это 0, а не `-Infinity`. В `IntonationReading` громкость не входит намеренно: в запись сессий она не идёт.
- `CentsReadout`: цифры меняются не чаще `centsReadoutIntervalMs` и только когда питч ушёл на `centsReadoutDeadbandCents` от **несглаженного** значения, с которого цифра показана (не от самой цифры — иначе 4.49 ↔ 4.51 мигает); смена ноты показывается сразу; диапазон ±99. На тишине и шуме сбрасывается.
- `noteSerial` растёт на ноте после тишины и на смене ноты; та же нота, удержанная через провал питча, — не новая. Экран будет пускать волну по смене счётчика: событие так переживает `conflate()`.
- `LiveState.glowTarget` (`LiveReducer.glowTargetOf`: 0 / `glowOff` / `glowNear` / `glowInTune` + остаток × `holdProgress`) и `LiveState.statusLine` (`statusLineOf`: null при звуке и без разрешения; в «Настройке» сообщение `TUNE_AUTO` / `TUNE_LOCKED`) приходят готовыми — экран по-прежнему не знает про `IntonationConfig`. Домен удержания (`HoldTimer`) не менялся: сглаживать спад будет экран.

## Конвейер домена
`PitchFrame` → `IntonationEngine.process(frame, TargetMode)` → `IntonationReading` (`Silence` / `TooNoisy` / `Active`). Движок — единственная точка сборки; остальные классы `core/domain` — его детали, у каждого свой тест.
- Время берётся только из `PitchFrame.tMs`: в домене нет часов и корутин, тесты подают кадры с шагом 10 мс (`TestFrames`). Движок не потокобезопасен — один коллектор.
- Движок считает всё от `freqHz`; поля `cents` / `midi` кадра он не читает (они для записи и отладки), в режиме «Настройка» центы считаются от струны.
- Порядок внутри: `SignalGate` (тишина / шум / провал) → кандидат ноты из сырого питча → `NoteLock` (100 мс) → `PitchSmoother` по дробному MIDI → `ZoneHysteresis` → `HoldTimer`.
- Два сглаживателя: кадры зафиксированной ноты идут в основной, кадры ещё не зафиксированного кандидата — в «ожидающий», который при фиксации становится основным. Поэтому новая нота стартует без «переезда» со старой, а одиночная октавная ошибка вообще не попадает в показание.
- Кадр чужого кандидата для текущей ноты равносилен провалу питча (`bridgeGap`): показание замирает, через `pitchGapToleranceMs` кольцо сбрасывается.
- Смена `TargetMode` (в том числе фиксация струны) полностью сбрасывает движок.
- `FakePitchSource.frameAt(index)` детерминирован и работает без корутин — используй его в `@Preview` и сценарных тестах. Параметры сценариев — в самом фейке, не в `IntonationConfig`.
- Известное свойство чисел из спеки: медиана 5 + EMA 0.3 ослабляют вибрато 5.5 Гц лишь до ~0.65 амплитуды, так что вибрато глубже ±14 центов вокруг ноля мигает в янтарный. «Режим вибрато» — v2; не «чини» это подкруткой констант без согласования.

## Что неочевидно в коде
- Токены зон и стили ноты не входят в Material-схему: бери их из `ViolinTheme.zoneColors` и `ViolinTheme.liveTypography` (CompositionLocal), стопы фонового градиента — `ZoneGradient.colorStops`. Сырые цвета в `Color.kt` — `internal`, напрямую из UI не использовать.
- Manrope — один вариативный TTF (`res/font/manrope_variable.ttf`), веса задаются через `FontVariation` (experimental API, opt-in локализован в `Type.kt`). Лицензия — `docs/licenses/Manrope-OFL.txt`.
- Маршруты навигации — строки из `TopLevelDestination`; type-safe routes потребовали бы плагин kotlinx.serialization, то есть новую зависимость.
- compileSdk 37 при targetSdk 36 — так задумано: этого требуют `core-ktx` и `lifecycle` из каталога версий, поведение рантайма не меняется.
- Макеты заглушек (`v1-stubs`) в хэндоффе нарисованы в половинном масштабе (206×446) — размеры оттуда умножай на 2.
