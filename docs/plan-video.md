# План реализации: видео-дубли

Поведение — в `docs/spec.md` (3.19, 5.13). Здесь — как это строится. Макет — `docs/design/project/video/project/Видео.dc.html`: кадры 20a (вход), 20b (лист разбора), 20c (карточка), 20d (экран сессии), 20e (на весь экран), 20f (лист ноты), 20g («Поделиться»), 20h («Звук»), секция `dev` с дополнением `ICONS`, `tokens`, `sizes`, `anims`, `texts`.

## Что берём из макета и что меняем

| Из макета | Решение |
|---|---|
| Одна контурная кнопка «Видео-дубль ⌄» 40 dp под текстом главной кнопки, меню из двух пунктов с подписями | Берём. Меню — тот же `DropdownMenu`, что у «Добавить» в нотах; α .38 во время звукового дубля и в режиме выбора — существующий `dimmedWhen` |
| Лист разбора с проявляющейся мини-лентой (20b2); простая полоса — запас (20b3) | Берём ленту: отрезки уже умеет считать `SessionRecorder.progress()` (полоса записи Live) — разбор отдаёт их потоком вместе с процентом. Полосу не делаем, пока лента не подведёт |
| Копирование — полоса без процентов | Берём |
| «Осталось» — по скорости первых 20 % | Берём; а вот «показывать ли лист» решается заранее — по коэффициенту, который меряется на устройстве по прошлым разборам (как `RenderSpeed` у «Поделиться»): в макете это одно правило, у нас два числа |
| «Отмена» у снятого → «Остановить разбор?» с «Продолжить разбор» | Берём; разбор под вопросом не останавливается. Закончился, пока вопрос открыт, — лист закрывается как «готово» |
| Ошибки строкой, «нет нот» у снятого — «Удалить» / «Отправить видео» | Берём. «Отправить видео» — существующий `ShareHost` с оригиналом файла |
| Карточка — вариант C: бейдж камеры 18 dp на краю плитки, вырез 2 dp цветом карточки | Берём. Вырез рисуется кольцом цвета фона карточки — фон анимируется (выбор, новый дубль), поэтому цвет выреза приходит в плитку параметром |
| Диалог удаления: «Видео (214 МБ), звук и разбор удалятся» — сумма по выбранным | Берём. Размеры читает view model при открытии диалога (файлы с диска), в состоянии — готовое число |
| Видео над итогом, ≤ 40 % высоты, вертикальное на полях | Берём |
| Прилипание: видео сжимается в строку 72 dp по прокрутке (20d3); запас — без прилипания (20d4) | Берём прилипание, но с оговоркой — см. «Риски»: картинка живёт в одном `TextureView`, который меняет размер от смещения прокрутки; если на телефоне это рвёт кадры — включается запасной вариант одной константой |
| «source of truth — ExoPlayer position» | **Не берём**: ExoPlayer в проекте нет и не будет (зависимость). Источник времени — позиция нашего `ChainSessionPlayer`, картинка — свой декодер, ведомый ею |
| Вход в полноэкранный режим — shared element 300 мс | Упрощаем: режим — состояние экрана сессии, а не маршрут (декодер и поверхность не пересоздаются, звук не прерывается); переход — рост рамки видео до экрана 300 мс. Системная «назад» сворачивает |
| Полоска нот ±4 с; в landscape с вертикальным видео — две половины по полям (20e4) | Полоску берём. Половины — **нет**: шкала времени с дырой посередине читается хуже, чем отсутствие полоски. С вертикальным видео в landscape полоска ложится на низ картинки вместе с панелью и уходит с ней |
| «Полоска отключается одной строкой в настройках плеера» | Настроек плеера нет (spec 3.8, раздел 7) — константа |
| Лист ноты перерисован (кружок 48, шкала ±50 ц, «ещё в 3 местах») | **Не берём** перерисовку: лист остаётся как в 3.10, добавляется только кнопка. «Слушать это место» у звуковых записей — берём, это та же кнопка |
| «дубль 7» с иконкой видео на экране сессии | Не берём: дубли не нумеруются (название — произведение и дата) |
| «Поделиться»: три варианта, чипы расширений, без обработки лист не пропускается | Берём |
| Размер ≥ 100 МБ — цветом `zone.near` | Цвет берём, токен — свой (`videoColors.sizeWarn`, тот же hex): цвета зон остаются про интонацию, как с `formError` |
| «Видео как снято» — сразу системный лист | Берём, но «сразу» требует не копировать 200 МБ ради красивого имени: в `cache/share/` кладётся жёсткая ссылка (`Os.link`, тот же раздел), копия — только если ссылка не удалась |
| Ошибка подготовки → «Отправить как снято» | Берём |
| «Звук» без картинки, значок видео в подзаголовке | Берём |
| Иконки `video`, `video-gallery`, `video-off`, `fullscreen`, `fullscreen-exit`, `play-circle`, `alert` | Берём в общий набор (+7). `play` / `pause` из дополнения — нет: у плееров общий залитый `PlayPauseGlyph` |
| Токены `video.field`, `video.scrim`, `video.panel`, `video.fullBg`, `badge.bg` | `ViolinTheme.videoColors`; `field` — тот же hex, что фон пюпитра, но свой токен |

## Решения, которых нет ни в спеке, ни в макете

- **Звук видео-дубля — дорожка самого видео.** У сессии `audioPath` указывает на `.mp4`, новый столбец `videoPath` (то же имя) говорит «здесь есть картинка». Плеер, форма волны, «Звук», рендер `.m4a` читают файл тем же `PcmDecoder` — он выбирает звуковую дорожку по MIME, правка минимальна. Отдельного извлечённого `.m4a` нет: не двоим место и не расходимся по времени. Потерянный файл = нет ни видео, ни звука.
- **Разбор** — `core/recording/FileTakeAnalyzer`: `PcmDecoder.read` → `FrameAnalyzer.push` → `IntonationEngine.process` (`TargetMode.Chromatic`) → `SessionRecorder.add`; наружу — `Flow<Progress(fraction, bars)>` и итог (`Saved(id)` / `NoNotes` / ошибка). Детектор — свой экземпляр из `PitchDetectorFactory` (они хранят буферы). Диспетчер — `@DefaultDispatcher`, `ensureActive` между кусками. Живёт в области `PieceViewModel`-а — нет: уход с экрана не должен рвать разбор, поэтому владеет им синглтон `VideoTakeImporter` со своим `CoroutineScope(SupervisorJob)`, view model только подписывается на его состояние (как `TakePipeline` переживает экран).
- **Чистое ядро разбора** (`TakeFileAnalysis` в `core/domain` / `core/audio`): на вход — источник хопов `ShortArray`, на выход — сессия. Тест на JVM: одна и та же синтетика через «как микрофон» и через файл-источник даёт равные отсчёты. `MediaCodec` — только в инструментальном тесте.
- **Файлы** — `VideoFiles` / `AppVideoFiles` рядом с `SessionAudioFiles`: `files/sessions/<uuid>.mp4` + `<uuid>-thumb.jpg`; съёмка идёт во временный `cache/camera/<uuid>.mp4` (эта папка уже открыта `FileProvider`-у) и переносится `renameTo` — без копии. Импорт из галереи — поток в `.part`, затем переименование. Миниатюра — `MediaMetadataRetriever.getScaledFrameAtTime` (API 27) / `getFrameAtTime` + своё уменьшение на 26.
- **Сведения о файле** — `VideoInfo` (длительность, ширина, высота, поворот, дата создания, есть ли звук) одним проходом `MediaMetadataRetriever`; дата — `METADATA_KEY_DATE`, разбор формата — чистая функция с тестом.
- **База v6**: `sessions.videoPath TEXT` — один `ALTER TABLE … ADD COLUMN` (как `pieceId` в v4). `DatabaseMigrationTest` стартует с v1–v5.
- **Картинка** — `core/audio/playback/VideoTrackRenderer`: `MediaExtractor` (видеодорожка) + `MediaCodec` на `Surface`, свой поток; ведётся `SessionPlayer.positionMs` и «играет / пауза». Кадр отдаётся `releaseOutputBuffer(index, true)`, когда позиция дошла до его времени; опоздавший > 50 мс — `false`. Перемотка: `seekTo(SEEK_TO_PREVIOUS_SYNC)` + докрутка без показа. Пауза — декодер стоит, последний кадр на поверхности. Поверхность — `TextureView` в `AndroidView` (меняет размер и живёт в прокрутке; `SurfaceView` в сжимающейся шапке даёт чёрные прямоугольники) — **единственный View-интероп в проекте**, правило CLAUDE.md про Canvas-only относится к Live.
- **Полноэкранный режим** — `SessionState.fullscreen`; `TextureView` один и тот же, меняется только его рамка; поворот — активность и так следует датчику. Панель — таймер `standPanelHideMs` (те же 3 с) по образцу пюпитра. `FLAG_KEEP_SCREEN_ON` — пока `playing && fullscreen`.
- **Сборка `.mp4`** — `core/audio/share/VideoShareRenderer`: звук — существующий путь `PcmDecoder → SoundChain → AAC`, но кодированные буферы идут не в свой `MediaMuxer`, а в общий с видеодорожкой; для этого `OfflineAacWriter` делится на «кодер» и «приёмник» (файл `.m4a` / дорожка общего мультиплексора). Видеосэмплы читаются `MediaExtractor.readSampleData` и пишутся как есть; `setOrientationHint` — из оригинала. Хвост зала делает звуковую дорожку длиннее видео — контейнер это допускает.
- **Отметка «скрипка звучала»** — `RunningPracticeStore.markSound(atEpochMs)`: сейчас ставит «сейчас»; нужен вариант со временем (конец съёмки = начало + длительность).
- **`HistoryCard.hasVideo`** из `SessionSummary.videoPath`; `RecordTile(hasVideo, cutout)`.

## Зависимости

Новых нет. Разрешений нет (`CaptureVideo` и `PickVisualMedia` их не требуют; `CAMERA` не объявляется — иначе системная камера по intent перестала бы открываться без него).

## Этапы

### Этап 36. Разбор по файлу

Файлы: `core/recording/FileTakeAnalyzer.kt`, чистое ядро и его источник хопов, `PcmDecoder` (выбор звуковой дорожки в контейнере с видео; отказ на частоте не 44.1 / 48), `RepertoireConfig` (пределы), результат и ошибки — sealed-типы.
Тесты: JVM — равенство «микрофон / файл» на синтетике, пределы (короче 2 с, длиннее 60 мин, нет нот), отмена, поток отрезков монотонен; инструментальный — настоящий `.mp4` со звуком (собирается в тесте `MediaMuxer`-ом из нашего AAC и синтетической видеодорожки либо лежит в `androidTest/assets`), файл без звука, скорость разбора (в logcat, как `SoundChainSpeed`).

## Как вышло

### Этап 36 — сделан

- Чистое ядро — `core/recording/TakeFileAnalysis` (`PcmSource` → целые хопы → `FrameAnalyzer` → движок → `SessionRecorder`), обёртка с декодером — `DecodingFileTakeAnalyzer` за интерфейсом `FileTakeAnalyzer` (биндинг в `AudioModule`). `PcmDecoder` править не пришлось: он и так ищет звуковую дорожку по MIME.
- Декодер отдаёт куски как придётся — ядро пересобирает их в хопы по 512: иначе результат отличался бы от микрофонного. Тест сверяет отсчёты «как с микрофона» и «из файла кусками по 300».
- Рекордер считает время от первого показания — первым идёт `Silence` с `tMs = 0`: ноты встают на время файла, а значит и картинки.
- Отрезки мини-ленты рекордер меряет от записанного времени (полоса Live растёт вместе с записью); здесь длина известна заранее — отрезки пересчитываются в доли всего файла. Паузы места не занимают, как на Live.
- Хвост короче хопа отбрасывается.
- `androidTest/.../testing/TestVideo` собирает на устройстве настоящий `.mp4`: картинка с яркостью по номеру кадра (пригодится перемотке на этапе 38) и звук нашим же AAC-кодером.
- Скорость на эмуляторе в отладочной сборке — 2.9× (`adb logcat -s FileTakeAnalysisSpeed`); стартовый коэффициент оценки в спеке поправлен на 0.35.

### Этап 37 — сделан

- База v6: `sessions.videoPath` (`MIGRATION_5_6` — один `ALTER TABLE`), `6.json` в `app/schemas`; `DatabaseMigrationTest` получил старт с v5 (звуковые таблицы раскладываются руками из `DatabaseMigrations.SOUND_COLUMNS`, он стал `internal`).
- Видео лежат в той же папке, что звук сессий (`files/sessions/<uuid>.mp4` + `<uuid>-thumb.jpg`), и `audioPath` видео-дубля — имя этого файла: `SessionAudioFiles.existing / delete / deleteOrphans` работают для видео без правок вызывающих. `AppSessionAudioFiles.delete` убирает и миниатюру; чистка сирот даёт всему, что не `.m4a`, сутки (`RepertoireConfig.orphanVideoMinAgeMs`), а миниатюру живого видео сиротой не считает. Интерфейс `SessionAudioFiles` не менялся — его реализуют пять тестовых фейков.
- `core/recording/video`: `VideoFiles` / `AppVideoFiles` (съёмка в `cache/camera/`, `adopt` — перенос переименованием, `import` — поток в `.part`, `info` — `MediaMetadataRetriever`, размеры «как видно», звук ищется экстрактором, а не ключом `HAS_AUDIO`; миниатюра — первый кадр, у тёмного — кадр на 1-й секунде), `VideoDates` (дата из метаданных; 1904 год — «даты нет»), `VideoTakeImporter` — синглтон со своей областью: состояние `VideoImport` (`Idle / Working / Failed`), событие `Saved`. `AnalysisSpeed` — как `RenderSpeed`.
- «Остановить разбор?» — флаг `asking` внутри `Working`: разбор идёт под вопросом. «Отправить видео» из вопроса разбор останавливает и переводит в `Failed(STOPPED)` с теми же двумя выходами — в макете этого кадра нет.
- Отметка «скрипка звучала» понижаться не может: ставится, только если позже уже стоящей.
- `ElapsedClock` переехал из `feature/share` в `core/di`: он нужен импортёру, а `core` не зависит от `feature`.
- Отправка оригинала (`ShareFiles.original`) — жёсткая ссылка `Os.link` вместо копии, копия — запасной путь; этим же путём уходит в системный лист снятое видео, не ставшее дублем.
- Экран: `VideoTakeButton` (слот `below` у `RecordTakeRow`), `VideoImportSheet` (`VideoTake.kt`). Лист не закрывается свайпом через `confirmValueChange = { it != Hidden }` — **не `{ false }`**: тот запрещает листу и раскрыться (так на эмуляторе лист сначала не показался вовсе).
- Мини-лента листа — отрезки в одну строку (у нас есть зона и доля, высоты нот в `RecordingBar` нет); семь рядов по высоте из макета не делал.
- Проверено на эмуляторе: меню, выбор видео системным пикером, лист разбора с проявляющейся лентой, дубль в списке с датой из файла, экран сессии видео-дубля (звук читается из `.mp4`), удаление пачкой уносит `.mp4` и миниатюры. Не проверено руками: съёмка системной камерой (`CaptureVideo`), все ветки ошибок и вопрос «Остановить разбор?» — они покрыты `VideoTakeImporterTest`; смерть процесса во время съёмки.

### Этап 38 — сделан

- `core/audio/playback/VideoTrackRenderer` за интерфейсом `VideoPicture` (`VideoPictureFactory` — в `SessionModule`): свой поток, вызовы оставляют «желания» под замком (`setSurface`, `follow`, `release`). Плеер не менялся: рендерер получает каждое его слово (`follow(positionMs, playing)`, раз в ~43 мс) и между словами несёт время сам по монотонным часам — не дольше 500 мс: замолчавший плеер картинку останавливает.
- Кадр показывается, когда звук дошёл до его времени (сон не дольше 10 мс за раз); опоздавший больше чем на 50 мс — отбрасывается. Прыжок звука (назад на > 100 мс или вперёд на > 1 с) — перемотка: к опорному кадру назад и докрутка без показа, прежний кадр стоит. В покое с нужным кадром на поверхности ничего не декодируется.
- Поворот картинки делает сам декодер (в формате дорожки есть `rotation-degrees`); размеры «как видно» отдаются в `VideoState`.
- Без поверхности декодера нет: `setSurface(null)` ждёт (до 500 мс), пока поток отпустит кодек, — поверхность, разрушенная под работающим кодеком, роняет его. Вернувшаяся поверхность получает новый декодер на том же месте.
- **Буфер нулевого размера — не «пустой кадр»**: декодер, рисующий на поверхность, размер может не сообщать вовсе. Пустым считается только голый маркер конца потока.
- Аппаратный декодер эмулятора (goldfish) на `ImageReader` не рисует («decoder function returned error») — у `VideoTrackRenderer` есть параметр `softwareDecoder`, только для инструментального `VideoPlaybackTest`. Тест читает яркость центра кадра и по ней узнаёт номер кадра (`TestVideo.lumaOf`).
- `SessionViewModel`: `VideoUi` в состоянии (`lost`, размеры, `showing`, `undecodable`, размер файла), `fullscreen`, `attachSurface(surface)` — метод, а не интент (поверхность — не состояние), `PlaySegmentClicked` («Смотреть / Слушать это место»). Картинка освобождается раньше плеера и раньше удаления файла.

### Этап 39 — сделан

- `VideoLayoutMath` (чистый, с тестами): рамка в пропорциях видео, блок не выше 40 % экрана, сжатие в строку 72 dp по смещению прокрутки, слова строки проявляются на последних 40 % пути, окно полоски нот ±4 с.
- `components/VideoBlock.kt`: `VideoSurface` — `TextureView` в `AndroidView`, **единственный View-интероп проекта**; `VideoFrame` — заглушка до первого кадра (индикатор только после 300 мс), тап = пауза со значком на 600 мс, «на весь экран» в углу; `VideoMissingRow`. `components/VideoScreens.kt`: `StickyVideo`, `FullscreenVideo` (панель прячется через 3 с, только пока видео играет), `NoteStrip`.
- Прилипание: видео лежит поверх прокрутки и сжимается от её смещения, под ним в прокрутке — распорка высотой блока. Запасной вариант без прилипания — `VIDEO_STICKS = false` в `SessionScreen.kt`. На эмуляторе сжатие идёт без мерцания.
- Полноэкранный режим — состояние того же экрана (`SessionState.fullscreen`): звук не прерывается, системная «назад» сворачивает. Вид при этом другой, и его поверхность может прийти раньше, чем уйдёт старая, — `SessionViewModel.attachSurface / detachSurface` сверяют поверхность по идентичности: картинку уносит только та, что в работе.
- **Кодек нельзя `flush()`-ить до его первого выхода**: он теряет конфигурационные данные, и аппаратный декодер (эмулятор — goldfish) падает на каждом кадре; программный прощает, поэтому `VideoPlaybackTest` этого не поймал. Рендерер: ничего не подано — `flush` не нужен; подано, но выхода ещё не было — перемотка ждёт первого выхода.
- Полоска нот делит высоту по нотам ленты (выше нота — выше отрезок), а не на семь рядов; в портрете у широкого видео она остаётся и без панели (лежит на чёрном поле), поверх картинки — только с панелью.
- Лист ноты: `NotePlace` — залитая «Смотреть это место» у видео, контурная «Слушать это место» у звука, у записи без звука кнопки нет.

### Этап 40 — сделан

- `SoundRenderer.renderVideo` (`SoundFileRenderer`): два прохода — звук существующим `render` во временный `.m4a`, затем один `MediaMuxer` берёт видеосэмплы оригинала как есть (времена, флаги, `setOrientationHint` из формата дорожки) и новый звук рядом, чередуя дорожки по времени. `OfflineAacWriter` на «кодер» и «приёмник» делить не пришлось — так решение проще и опирается на уже проверенный рендер; цена — временный файл со звуком (сотни КБ).
- При нейтральных настройках `render` цепочку не вызывает вовсе (без задержки ограничителя и хвоста): так делается «Только звук» у видео-дубля без обработки.
- `ShareVariant.SOUND`; `ShareInfo` знает имя `.mp4`, разрешение и «обработка что-то делает»; у видео-дубля лист показывается всегда (без обработки — «Видео» и «Только звук»), недоступный вариант выбрать нельзя. «Видео как снято» — жёсткая ссылка, без подготовки. Ошибка подготовки предлагает «Отправить как снято».
- В листе: чипы `.mp4` / `.m4a`, строка файла с разрешением и размером; от 100 МБ размер цветом `videoColors.sizeWarn` и словами. MIME отправки — по расширению.
- Заголовок подготовки остался общим («Готовим файл»): состояние `Preparing` не знает варианта, а у «Только звук» слово «видео» было бы неверным.
- Инструментальный `VideoShareRenderTest`: видеосэмплы совпадают с оригиналом по временам и размерам, поворот сохранён, звук длиннее на хвост зала, отмена и сбой ничего не оставляют. На эмуляторе: 40 с видео готовятся ~25 с (отладочная сборка), файл уходит в системный лист.

## Риски

- **Прилипание с `TextureView`**: изменение размера поверхности на каждом кадре прокрутки может давать рывки или мерцание на части устройств. Запас — `VIDEO_STICKS = false` (видео уезжает с прокруткой, кадр 20d4). Решается на телефоне.
- **Звук из приложения камеры**: автоусиление и шумоподавление меняют уровни; порог тишины −45 dBFS и `clarityThreshold` подбирались под наш `AudioRecord`. Если на телефоне разбор видео теряет тихие ноты — отдельные пороги для файлов в `IntonationConfig`, не подкрутка общих.
- **Кодеки**: HEVC, 4K, 60 fps, 10 бит — декодер телефона обычно справляется, эмулятор — нет. Нераспознанный формат видеодорожки не должен мешать разбору: разбор идёт по звуку; если картинку показать нельзя — экран ведёт себя как у «видео не найдено», но звук остаётся. Это отдельная ветка состояния, в макете её нет.
- **Переменная частота кадров и B-кадры** при копировании сэмплов: времена и флаги берутся из экстрактора как есть — `MediaMuxer` это принимает, но проверяется инструментальным тестом на файле с настоящей камеры эмулятора.
- **Место**: снятое видео сначала лежит в `cache/` — система может вычистить кеш при нехватке места, пока идёт разбор. Перенос в `files/` делается сразу после возврата из камеры, до разбора.
- **Смерть процесса во время съёмки** (камера вытесняет приложение): путь файла — в `SavedStateHandle`, как у фото нот; по возвращении разбор стартует из восстановленного состояния.
- Синхронность картинки и звука, ощущение от перемотки — только на телефоне; на эмуляторе проверяется логика, не ощущение.
