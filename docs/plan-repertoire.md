# План реализации: репертуар — произведения, ноты, дубли

Поведение — в `docs/spec.md` (3.15, 5.9, §6). Здесь — как это строится: что берём из макета, типы, этапы, тесты, риски. Макет — `docs/design/project/repertoire/project/Репертуар.dc.html`: кадры 13a–13h, секция `dev` с массивами `tokens`, `sizes`, `anims` и двумя абзацами текстов и правил.

## Что берём из макета и что меняем

| Из макета | Решение |
|---|---|
| Слово — «произведение»; вход — переключатель «Сессии | Репертуар» под заголовком «Записей», тот же компонент, что на Live; положение запоминается | Берём. Запоминается, пока жив процесс (в памяти `HistoryViewModel`-соседа), в DataStore не пишем |
| В «Сессиях» дубль подписан названием произведения и тихим чипом «дубль»; свободная сессия — «Сессия» | Чип берём. Названия — по спеке: у свободной «Сессия · 14 сентября», у дубля «Менуэт соль мажор · 18 сентября»; после удаления произведения дубль снова «Сессия · …» |
| Карточка произведения: миниатюра 54×72 с плёнкой 18 %, без нот — плашка с контуром листа; балл справа цветом, без дублей «—» | Берём |
| Пусто под фильтром: «Ничего со статусом „…“. Показать все» (с действием) | Берём вместо текста спеки 0.18 |
| Порядок блоков: шапка → ноты → запись → заметки → прогресс → дубли; запись — строка «кнопка + подпись» без заголовка | Берём; совпало со спекой |
| Лента нот: плитки 84×112, номер капсулой, справа «+ Добавить», первая плитка с плёнкой 10 % | Берём |
| **Две кнопки добавления: «Сфотографировать» (первой) и «Из галереи»** | Берём: ноты обычно лежат на пюпитре, а не в галерее. В спеке 0.18 камера была отложена — переносим в v1. Системная камера через `TakePicture` + `FileProvider` (он в `androidx.core`, зависимость уже есть); разрешение `CAMERA` не объявляем — системной камере оно не нужно |
| Запись вслепую: 14 столбиков `onSurfaceVariant`, высота и α от громкости, ~20 раз/с, EMA 120 мс; служебные состояния строкой с контурной точкой `status.blocked` | Берём. Столбики — «бегущая» история громкости (новый справа), а не спектр: частот у нас нет |
| Новый дубль: вставка сверху, подсветка `take.new` + кольцо primary, гаснет за 1.5 с; список сам не прокручивается | Берём |
| Тональность: три ряда (тоника 7 клеток, знак ♭ ♮ ♯, лад), повторный тап по тонике снимает выбор; **немецкая запись**: мажор с прописной, минор со строчной, ♯ → is, ♭ → es; «B-dur» — си-бемоль | Берём, и доводим правило до конца: си-бекар — «H» («h-moll»), си-бемоль — «B», ми- и ля-бемоль — «Es», «As» (не «Ees», «Aes»). Чистая функция с тестами на все 42 сочетания |
| Темп: степпер ±1 с автоповтором (через 600 мс шаг 5), чипы 80 · 100 · 120, пусто «—» | Берём; степпер — существующий `Stepper` из «Занятий», ему добавляется ускоренный шаг |
| Форма: «Сохранить» в шапке, крестик слева, диалог «Не сохранять?» при уходе с правками; ошибка названия — рамка и подпись «Без названия не сохранить» | Берём |
| Токен `error` = hex `zone.off` «как единственное исключение» | Отдельный токен `formError` с тем же hex: цвета зон в коде остаются только про интонацию |
| Пюпитр: фон #0E0E12, градиентные поля вместо плашек, панель прячется через 3 с, таблетка записи 56 dp, капсула «● 1:12 · 2 / 7» при спрятанной панели, зоны пунктиром один раз при первом входе + тост, подсветка края при перелистывании, отскок на крайних страницах, двойной тап 1× ↔ 2×, сброс масштаба при смене страницы | Берём. «Первый вход» — флаг в DataStore. Пейджер — `HorizontalPager` из `compose.foundation` (уже в BOM) |
| Landscape экрана произведения: левая колонка 300 dp (название, запись, прогресс) фиксирована, правая прокручивается | Берём |
| Тосты — Snackbar 3 с | Остаёмся на `Toast`, как во всём приложении: `Scaffold` со snackbar-хостом ради трёх сообщений не заводим |
| «Последняя активность» — дубль, правка, **фото** | Берём: добавление и удаление страницы обновляет время правки |

## Решения, которых нет ни в спеке, ни в макете

- **Связь сессии с произведением** — столбец `pieceId` в `sessions` (nullable, с индексом), без внешнего ключа: миграция — один `ALTER TABLE … ADD COLUMN`, а отвязка при удалении произведения — в той же транзакции DAO, что и удаление. Внешний ключ потребовал бы пересоздания таблицы сессий — риск для чужих данных без выгоды.
- **Страницы** — таблица `sheet_pages` с внешним ключом на произведение (`ON DELETE CASCADE`); файлы удаляет репозиторий (сначала строки, потом файлы), сироты чистятся при старте — как звук сессий.
- **Два файла на страницу**: страница (длинная сторона ≤ 2560 px, JPEG 88) и миниатюра (≤ 320 px). Общий код чтения, поворота по EXIF и уменьшения выносится из `AvatarImage` в `ImageImport`; аватар — его частный случай (квадрат 512).
- **Импорт фото не блокирует экран**: плитки-заглушки — состояние ViewModel; строка страницы пишется, когда файл готов. Смерть процесса посреди импорта оставляет файл-сироту, его уберёт чистка.
- **Камера**: снимок пишется системной камерой во временный файл в `cache/`, затем идёт тем же импортом, что фото из галереи; временный файл удаляется.
- **Конвейер записи** выносится из `LiveViewModel` в `core` одним классом (`TakePipeline`: источник → движок → рекордер → звук, правила 3.9), параметризованным тем, показывать ли показания. `LiveViewModel` становится его потребителем; поведение Live не меняется — его 36 тестов должны пройти без правок по смыслу. Экран произведения и режим пюпитра делят одну запись: конвейер живёт в `PieceViewModel`, пюпитр — маршрут внутри того же графа с общей ViewModel, поэтому переход между ними запись не рвёт.
- **Отметка «скрипка звучала»** для занятий уезжает в конвейер вместе с остальным — работает и на Live, и при дубле.
- **Название дубля** не хранится: у сессии `title = null`, карточка строит «‹название произведения› · дата» из связи. Переименованный вручную дубль хранит своё имя, как любая сессия.
- **Прогресс и «лучший»** — чистые функции от списка сессий произведения (`PieceStats`), отдельно не хранятся.

## Зависимости

Новых нет: `HorizontalPager` — в `compose.foundation`, `FileProvider` — в `androidx.core`, выбор и съёмка фото — в `activity-compose`.

## Этапы

Каждый этап — отдельные коммиты, обе Gradle-команды зелёные, проверка на эмуляторе, обновление `CLAUDE.md`.

### Этап 21. Домен и хранение
1. `feat(domain): repertoire — piece, key, status, rules and stats` — `RepertoireConfig`, `Piece`, `PieceStatus`, `MusicalKey` (немецкое имя), `PieceDraft` → правила полей, `SheetPage`, `PieceStats` (последняя активность, лучший дубль, ряд прогресса), интерфейс `RepertoireRepository`. Тесты: все сочетания тональностей, обрезка и пустое название, границы темпа, лучший при равенстве, порядок по активности.
2. `feat(data): pieces and sheet pages, sessions linked to a piece, database v4` — сущности, DAO, `MIGRATION_3_4`, `pieceId` в сессиях (`NewSession`, `SessionSummary`), отвязка при удалении. Инструментальные: `RoomRepertoireRepositoryTest`, `DatabaseMigrationTest` (v3 → v4: сессии, занятия, трофеи целы; старые сессии без произведения).
3. `feat(data): sheet photo storage` — `ImageImport` (общий с аватаром), `SheetFiles` (страница + миниатюра, удаление, сироты); инструментальный тест; чистка сирот в `AppStartViewModel`.

### Этап 22. Список и произведение без записи
1. `feat(history): «Сессии | Репертуар» switch and the repertoire list` — переключатель, список, фильтр, пустые состояния, чип «дубль» и названия дублей в карточках сессий.
2. `feat(repertoire): piece form` — создание и правка, тональность, темп, статус, ошибки, диалоги удаления и несохранённых правок.
3. `feat(repertoire): piece screen` — шапка с меню статуса, лента нот, добавление из галереи и камерой (`FileProvider`), заметки, пустые состояния, landscape.

### Этап 23. Дубли
1. `refactor(live): recording pipeline moves out of the view model` — без изменения поведения.
2. `feat(repertoire): blind takes` — запись на экране произведения, индикатор уровня, состояния микрофона, список дублей, подсветка нового, прогресс, «лучший».

### Этап 24. Режим пюпитра
1. `feat(repertoire): music stand` — пейджер, масштаб, трети экрана, панель, подсказка первого входа, удаление страницы, `FLAG_KEEP_SCREEN_ON`, landscape.
2. `feat(repertoire): take recording from the stand` — общая запись с экраном произведения, капсула при спрятанной панели.
3. `docs:` — spec (отметки «реализовано»), `CLAUDE.md`.

## Риски

- **Рефакторинг конвейера записи** — самое хрупкое место приложения (звук, сохранение при сбоях). Делается отдельным коммитом без новой функциональности, под существующими тестами.
- **Память на фото**: страница 2560 px — это ~25 МБ в памяти; в пюпитре держим текущую и соседние, декодируем с `inSampleSize` под экран, полное разрешение — только при увеличении.
- **Камера на эмуляторе** снимает виртуальную сцену — для проверки годится; на телефоне проверяет владелец.
- **Жесты пюпитра**: тап по третям, свайп пейджера, щипок и двойной тап делят один экран — порядок распознавания проверяется руками.
