# План реализации: «Занятия» — учёт времени

Поведение — в `docs/spec.md` (3.12, 5.6, §6, §4). Здесь — как это строится: пакеты, типы, этапы, тесты, риски. Макет — `docs/design/project/practice/project/Занятия.dc.html`: кадры 10a–10j, секция `dev` с массивами `tokens`, `sizes`, `anims`, логика ступеней в JS (`steps`, `stepOf`, `fmt`).

## Что берём из макета и что меняем

| Из макета | Решение |
|---|---|
| Четыре фиолетовых тона заливки `practice.1–4`, точка под числом, легенда «меньше — больше» | Берём: новые токены в `ViolinTheme`, не в Material-схеме |
| Кольца «сегодня» (onSurface 1.5 dp) и «выбранный» (primary 2 dp с зазором), одно кольцо когда совпадают + чип «сегодня» | Берём |
| Смена месяца стрелками; свайп — «можно, но не обязателен» | Свайпа нет: спорит с вертикальной прокруткой экрана, сам дизайнер считает его лишним |
| Лист правки времени: степпер ±5 с автоповтором + чипы «+10 · +30 · +1 ч · 0» | Берём; предел 12 ч — зажим, а не ошибка |
| Диалог «Занятие не закончено», вариант без звука с кнопкой «Изменить время» | Берём; «Изменить время» открывает лист итога со степпером |
| Чип занятия на Live под переключателем, ряд струн под чипом; landscape — первым в правой колонке | Берём |
| Полоса записи подписана «запись · 01:24» | Слово берём, формат таймера — наш `м:сс` без ведущего нуля, как у таймера занятия (`12:34`, `1:02:34`): один формат на оба таймера |
| Кольцо Live в макете сжимается 300 → 280 → 260 под чип и полосу | Не задаём руками: `LiveLayoutMath` уже считает диаметр от свободной высоты, чип просто уменьшает её |
| Landscape-панель 64 dp, значок и подпись в строку | Берём на всех вкладках, кроме Live (там панели нет) — одна раскладка панели в landscape, а не только на «Занятиях» |
| Подсказка «Настройки» в кадре 10h3 — «Ля · 440 Гц» | Латинские названия, как в spec 3.6 |
| Стрелка «вперёд» при показе текущего месяца — alpha .3 | Берём: кнопка disabled |

## Зависимости

Новых нет. Миграция базы тестируется без `room-testing`: инструментальный тест сам создаёт файл базы версии 1 (`SQLiteDatabase`, `CREATE TABLE` из `app/schemas/…/1.json`), кладёт сессию с отсчётами, открывает через Room с миграцией и проверяет, что сессия читается, а таблица занятий работает. Room при открытии такой базы сверяет схему с ожидаемой — это и есть проверка миграции. Если тест окажется хрупким, `androidx.room:room-testing` — отдельное согласие.

## Архитектура

```
core/domain/practice        чистый Kotlin
  PracticeConfig             числа spec 5.6
  PracticeEntry              сохранённое занятие: дата (LocalDate), начало, длительность, manual
  RunningPractice            идущее занятие: начало и время последнего звука
  PracticeStats              суммы по дням / неделе / месяцу, ступень заливки, серия
  ForgottenPractice          правила забытого занятия: идёт / забыто / истекло (12 ч)
  PracticeRepository         интерфейс: entries (Flow), add, replaceDay
  RunningPracticeStore       интерфейс: running (Flow), start, markSound, clear
core/data/practice           Room: PracticeEntity, PracticeDao, RoomPracticeRepository; миграция 1 → 2 в AppDatabase
core/settings                DataStoreRunningPracticeStore (тот же файл DataStore, что настройки)
core/ui/format/Formats       «45 мин», «1 ч 25 мин», «2 ч»; таймер `м:сс` / `ч:мм:сс`; «17 сентября, четверг»; «Сентябрь 2026»; «18:42»
feature/practice             PracticeContract / ViewModel / Screen / Route; components: PracticeCalendar, DaySection, SummarySheet, EditTimeSheet, ForgottenDialog
feature/live                 чип занятия (LiveState.practice), отметка звука
navigation                   вкладка «Занятия», «История» → «Записи», отметка на значке, landscape-панель
```

Принципы те же, что у сессий: экраны stateless, MVI, числа в `PracticeConfig`, время — из внедряемого `Clock` (для таймера — тикающий поток на его основе), в домене нет системных часов.

Ключевые решения:
- Идущее занятие — в DataStore (переживает перезапуск), законченное — строка в Room. Дата занятия считается в момент сохранения по поясу устройства и хранится строкой ISO (`2026-09-17`): дальше она не зависит от пояса.
- «Изменить время» — транзакция: удалить все занятия дня, вставить одно с `manual = true` (при нуле — только удалить). Начало такого занятия — полдень этого дня по местному поясу: поле обязательное, а смысла у него для ручной записи нет.
- Сводка и календарь считаются из всех строк таблицы в памяти: занятие — одна строка в день или несколько, за год это сотни строк, агрегировать в SQL незачем.
- Таймер на экране и в чипе — `Clock` раз в секунду, от `startedAtEpochMs`; ничего не копится в памяти, перезапуск не страшен.
- Отметка «скрипка звучала» ставится из `LiveViewModel` при `IntonationReading.Active` не чаще раза в минуту — запись в DataStore редкая.
- Проверка забытого занятия — при каждом `ON_START` активности (открытие приложения и возврат из фона), в `AppStartViewModel`; диалог и лист итога показываются поверх любой вкладки.

## Этапы

Каждый этап — отдельные коммиты, обе Gradle-команды зелёные, проверка на эмуляторе на сборке `-PfakePitch=true`, обновление `CLAUDE.md`.

### Этап 12. Домен и хранение
1. `feat(domain): practice config, stats and forgotten-practice rules` — `PracticeConfig`, `PracticeEntry`, `RunningPractice`, `PracticeStats`, `ForgottenPractice`, интерфейсы репозиториев.
   Тесты: суммы по дням (несколько занятий в день, ручные), неделя с понедельника (включая понедельник и воскресенье, границу месяца), месяц; ступени на границах 19/20, 44/45, 89/90 мин; серия (с сегодняшним, без сегодняшнего — с вчерашнего, пропуск обнуляет, пусто); забытое занятие: до 60 мин — идёт, звук старше 60 мин — забыто с временем звука, без звука и старше 60 мин — забыто без времени, старше 12 ч — истекло с концом по звуку или начало + 1 ч.
2. `feat(data): practice entries in room` — `PracticeEntity`, `PracticeDao`, `RoomPracticeRepository`, `AppDatabase` v2 + `MIGRATION_1_2`, схема `2.json`; Hilt.
   Тесты: маппинг сущность ↔ домен на JVM; инструментальные — DAO (add, replaceDay, ноль удаляет) и миграция (сессия версии 1 читается после миграции).
3. `feat(settings): running practice in datastore` — `DataStoreRunningPracticeStore`; тест на JVM на временном файле.
4. `feat(ui): practice formats` — `Formats`: длительность словами, таймер, дата с днём недели, месяц с годом, время суток; тесты.

### Этап 13. Экран «Занятия»
1. `feat(practice): contract and view model` — состояние: идёт ли занятие и с какого времени, «сегодня», сводка, месяц календаря с ступенями по дням, выбранный день с временем и его сессиями, листы (итог, правка), пустое состояние. Интенты: старт, стоп, сохранить / не сохранять итог, выбор дня, месяц назад / вперёд, правка времени. Эффекты: перейти на Live, открыть сессию, тост «Слишком коротко». Тесты на фейковых репозиториях.
2. `feat(practice): screen` — кнопка / таймер, сводка, календарь (`Canvas` для клеток или `Layout` из `Box` — по 42 клетки, обычная композиция), выбранный день с карточками сессий (компонент карточки из «Записей» становится общим), листы, пустое состояние, landscape. Превью: 10a, 10b, 10c1, 10c2, 10g, 10j.
3. `feat(nav): practice tab` — четыре вкладки, значок «Занятия» с отметкой, «История» → «Записи» (строка, заголовок, маршрут не меняется), компактная панель в landscape.

### Этап 14. Связь с Live
1. `feat(live): practice chip` — `LiveState.practice`, чип под переключателем и в landscape, тап → «Занятия»; отметка «скрипка звучала» из `LiveViewModel`. Тесты: отметка не чаще раза в минуту, только при `Active`.
2. `feat(practice): forgotten practice` — проверка при `ON_START`, диалог 10f1 / 10f2, автозавершение после 12 ч с листом итога; «Начать занятие» → Live. Тесты ViewModel на сценариях из этапа 12.

## Риски

- **Схема базы**: первая миграция в проекте. Инструментальный тест на настоящем файле обязателен; на эмуляторе владельца стоит проверить, что сессии после обновления на месте.
- **Часовые пояса**: «сегодня», неделя и месяц — по поясу устройства на момент просмотра; дата занятия — по поясу в момент сохранения. Тесты идут с явным `ZoneId`, чтобы это не расходилось.
- **Таймер по часам**: перевод системного времени назад даст отрицательную длительность — зажимается в ноль; вперёд — «забытое занятие» сработает раньше времени, это допустимо.
- **Два таймера на Live**: в макете они разведены по краям и словами; если на живом экране всё же путаются — вопрос к дизайну, не к коду.
