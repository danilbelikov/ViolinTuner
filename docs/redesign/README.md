# Редизайн Violin Journey (сентябрь 2026)

Папка — всё, что нужно, чтобы реализовать новый дизайн приложения в отдельном чате. Здесь **только добавлено новое**: спека (`docs/spec*`), заметки (`docs/notes`), хэндофф (`docs/design/project`) и код не менялись. Пока редизайн не перенесён в спеку, **источник правды по поведению — по-прежнему `docs/spec.md` и `docs/spec/*`**. Макеты этой папки — предложение, одобренное владельцем как направление («Занятия» — вариант A, четыре вкладки, остальное — «переделай, как тебе кажется»).

Макеты сделаны 27.09.2026 скиллом `mobile-ux-design` (психология восприятия: зона большого пальца, Фиттс, Хик, гештальт, без тёмных паттернов). 28.09.2026 макеты сверены с кодом и спекой (аудит), а недостающее дорисовано тем же скиллом — ещё шесть страниц. Итоги аудита — в `implementation/*.md`, разделы «Правила переноса: что не нарисовано», «Решения по расхождениям со спекой», «Перед стартом этапа». Потом страницы сверены между собой; где они спорили, решено в `implementation/decisions.md` («Решил я при подготовке») и внесено в `implementation/*.md`.

**Кто прав, если источники спорят:** по поведению и числам домена — спека; дальше — `decisions.md` и `00-global.md`; потом файл раздела `NN-*.md`; потом макет. Что на старых страницах осталось поправить при своём этапе — таблица «Где страницы расходятся» в `mockups/index.html`.

## Как передать в новый чат

Скопируй в новый чат примерно такой запрос:

> Реализуем редизайн из `docs/redesign/`. Прочитай `docs/redesign/README.md`, `implementation/00-global.md`, `implementation/stages.md`, `implementation/decisions.md` и `implementation/open-questions.md`. Начинаем с этапа R1, макет — `mockups/components.html`. Папка `docs/redesign/` уже в git отдельным коммитом `docs(redesign): …` (0.78 — 4085212f); если правишь её дальше — коммить с явным путём: `git add docs/redesign`, `git commit -m "…" -- docs/redesign` — в индексе лежат `.idea/*`. Сначала — подраздел R1 в `docs/spec/redesign.md` (00-global, «Как переносить в спеку»), покажи план файлов, потом код.

Дальше по одному этапу за раз: `stages.md` говорит, какой файл `implementation/NN-*.md` читать и какие макеты открыть; в самом файле сначала — «Перед стартом этапа».

## Главные решения одной строкой

- Четыре вкладки: **Занятия · Live · Репертуар · Записи** (репертуар вынут из «Записей»; подтверждено владельцем 28.09).
- Спека — надстройкой `docs/spec/redesign.md` (3.36 / 5.29, версии с 0.79, этапы с 100; события — прежние 96–99).
- Главное действие каждого экрана — **закреплено внизу**, в зоне большого пальца (`AppDock`). В landscape dock — у колонки, к которой относится действие (обычно левой; у экрана события — правой); листы — не шире 640 dp. На 360×640 кнопка и панель стоят всегда, первым сжимается окно дома.
- «Занятия» — вариант A: строка пути с кольцом уровня, карточка «Сегодня» с неделей, напоминание о событии, дом ниже, календарь под сгибом, день — листом.
- Цвет = один смысл: зоны — только интонация; фиолетовый — время и действие; тёплый — серия; латунь — сделано; мягкий коралловый #FFB199 — только опасное: действия, предупреждения о потере данных, сбои (`DangerSoft`, заменяет и удаляет красный `Destructive`; ошибка ввода в поле — серым со значком). На Live нет оранжевого дерева; стекло поверх картин (.72, и карточки Live тоже; .82 — только над пёстрым) — без размытия.
- Ядро Live (кольцо, нота, слово, цифры, свет, все числа домена) **не меняется**.
- Без стыжения: нулевая серия не показывается, «Не сохранять» не красная; смахнуть лист — только скрыть.
- События (R9): цвета, знаки и клетка календаря — только `events-kinds.html`; `practice-sheets.html` 8–11 — только раскладка. Клетку календаря сразу окончательной строит R2.
