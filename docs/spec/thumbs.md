## 3.38 Кадр видео в списках

> Черновик 0.92, сделан этапами 131–132 (04.10.2026; проверен на эмуляторе Android и в симуляторе iOS, на телефонах — нет; раздел 8) — по просьбе владельца 04.10.2026: «чтобы для видео в списках, где иконка видео, был не просто значок, а взятый из видео кадр — понимать, что там за ролик». Макет — `docs/design/project/thumbs/project/thumbs.html` (списки, выбор, все состояния плитки, какой кадр, отклонённые варианты). Меняет: 3.19 — «В списках» (камера → кадр), «Разбор» (миниатюра первого кадра → кадр из середины видео); 5.13 — «Миниатюра» (какой кадр); 3.21 и 3.36.5 — «Карточка записи» (у записи с видео плитка — кадр, а не круг с камерой). Новых полей в базе нет, файл миниатюры прежний — `<uuid>-thumb.jpg` рядом с видео (5.13).

Зачем. Видео-дубли одного произведения называются датой (3.21), и у всех на карточке одна и та же камера: какое из них какое, не понять, пока не откроешь. Кадр из самого видео узнаётся сразу — дома или на сцене, одна или с педагогом, в концертном или в домашнем.

**Плитка с кадром**

- У записи с видео, чей файл на месте, вместо круга с камерой стоит кадр из этого видео: скруглённый квадрат той же ширины, что круг (5.31). Названия и строки всех карточек по-прежнему начинаются с одной линии, край списка не ломается, режим выбора не прыгает. Форма говорит, что внутри: звук — круг со знаком, видео — квадрат с картинкой.
- Кадр заполняет квадрат целиком, лишнее обрезано: у горизонтального видео — слева и справа, у вертикального — больше снизу, чем сверху: в вертикальном кадре лицо и скрипка — в верхней половине.
- Поверх кадра ничего нет — ни плёнки, ни знака: картинка сама и есть знак, а середина кадра — самое узнаваемое место. Что это видео, строка карточки говорит словом, как раньше («· видео», у записи события — слово её вида, 3.36.5, 3.36.9), TalkBack — первым словом описания.
- Пока кадр читается с диска — квадрат цвета плитки с камерой посередине; прочитанный кадр проявляется поверх (5.31). Кадр, показанный недавно, стоит сразу, без проявления: список, прокрученный туда и обратно, не мигает.
- Миниатюры нет (её не удалось сделать — телефон не декодирует картинку этого видео, 3.19) — прежний круг с камерой. Видео потеряно — прежний контур с камерой, как у записи без звука (3.19, 3.20): от видео, которого нет, кадр не показывается, даже если файл миниатюры остался.
- Режим выбора (3.18) — как у круга: плитка сменяется отметкой выбора той же ширины, вышли из выбора — кадр вернулся. Подсветка свежего дубля и нажатие — как у любой карточки.

**Где**

- Все списки с карточкой записи: «Записи», «Записи этого дня» в листе дня (3.36.2), дубли на экране произведения (3.36.4), записи на экране события (3.36.9), лист «Слушать на…» «Звука записей» — и сама строка «Слушать на» (3.36.5).
- «Выступления» (3.36.9) — как были: там кадр последнего видео стоит в конце строки, со знаком воспроизведения; кадр тот же и показывается по тем же правилам, что в списках (5.31).
- Пустые состояния «Записей» (плитка 72 со знаком видео у «Видео пока нет», 3.36.5) — без кадра: видео там нет.

**Какой кадр**

- Кадр из середины видео. Видео со штатива обычно начинается с руки у телефона и шага к пюпитру, а кончается шагом обратно — в середине уже играют. Середина тёмная (погас свет, затемнение между пьесами) — берётся первый кадр, а если и он тёмный — кадр на 1-й секунде (прежнее правило 5.13); тёмные все — середина.
- Кадр делается один раз, когда видео попадает в приложение: снято системной камерой или выбрано из галереи (3.19), снято своей камерой под минусовку (3.32), добавлено к событию (3.35). Его же показывают лист разбора («это то видео», 3.19) и «Выступления».
- Миниатюры, сделанные до 0.92 (первый кадр), переделываются по новому правилу один раз — при первом запуске новой версии, в фоне, по одной. Пока проход не закончен, у видео в списках прежняя камера, а в «Выступлениях» — число записей; кадры встают все разом, когда переделаны все. Показывать кадры по мере переделки нельзя: кадр, прочитанный до переделки, приложение держит в памяти по имени файла, и старая миниатюра осталась бы на экране до перезапуска. Видео без миниатюры в том же проходе получает её, если кадр из него достаётся. После восстановления копии данных старой версии (3.20) её миниатюры переделываются так же.
- Оригинал видео не трогается (3.19): из него только читается кадр. Миниатюра — производное от видео, её можно переделать в любой момент; в копии данных она едет вместе с видео, как раньше (3.20).

**Слова и TalkBack** — новых слов нет. Описание карточки прежнее (3.36.5): «видео, …» первым словом; кадр декоративный, TalkBack его не читает.

**Landscape, маленький экран и крупный шрифт** — плитка той же ширины, раскладки не меняются.

## 5.31 Кадр видео в списках

> Черновик 0.92 (3.38). Размеры — рядом с плиткой (`RecordTile`), выбор кадра и имя миниатюры — `VideoThumbs` (общий код), умолчания миниатюры — `RepertoireConfig`.

- Плитка с кадром — 40 × 40 dp (ширина круга `RecordTileSize.CARD`), скругление 10 dp, подложка `surfaceContainerHigh`, под кадром — камера 22 dp `onSurfaceVariant`. Обрезка — `ContentScale.Crop` с выравниванием по вертикали −0,5 (`BiasAlignment(0, −0,5)`): у вертикального кадра 9 : 16 видна полоса примерно с 11 % по 67 % его высоты; горизонтальному выравнивание по вертикали ничего не меняет.
- Проявление прочитанного кадра — 150 мс (прозрачность 0 → 1); кадр из памяти (последние 48 картинок приложения, `rememberSmallFileImage`) и при «убрать анимации» («Уменьшение движения» на iOS) — сразу.
- Кадр — на половине длительности, ближайший опорный (Android — `OPTION_CLOSEST_SYNC`, iOS — допуски `AVAssetImageGenerator` по умолчанию). Запасные — 0 с и 1 с. «Тёмный» — прежнее правило: средняя яркость по сетке 16 × 16 ниже 16 из 255. Длительность неизвестна — только 0 с и 1 с, как до 0.92.
- Миниатюра — прежняя: JPEG 85, длинная сторона 320 px (`thumbMaxSidePx`), `<имя видео без расширения>-thumb.jpg` рядом с видео — без расширения любого вида: у видео с iPhone (`.mov`), пришедшего на Android копией данных, миниатюра теперь находится (до 0.92 Android искал `<uuid>.mov-thumb.jpg`). Пишется через `…-thumb.jpg.part` и встаёт на место переименованием: прежняя заменяется целиком, недописанного файла никто не видит.
- Путь к миниатюре читает хранилище записей вместе с файлом звука (3.20: нет файла — нет звука): только у записи с видео, чей файл найден, только если миниатюра есть и только когда отметка правила (ниже) — текущая (`SessionSummary.thumbPath`). Карточка (`HistoryCard.thumbPath`), строка «Слушать на» (`RecordingName.thumbPath`) и строка «Выступлений» (`PerformanceCard.thumbPath`) берут его оттуда; когда отметка встаёт, список записей приходит заново — уже с путями.
- Переделка — один раз за правило: отметка `video_thumbs_rule` в файле настроек (DataStore); правило 0.92 — 2, отметки нет — 1. Отметка ниже правила — при старте (`Housekeeping.atStart`) миниатюры записей с видео, чей файл найден, переделываются по одной, новые записи первыми; когда пройдены все, ставится отметка (неудача одного видео проход не останавливает). Прерванный проход (приложение закрыли) при следующем запуске идёт сначала. Отметка едет в копии данных вместе с настройками (3.20): копия старой версии приносит и старые миниатюры, и настройки без отметки — их переделывают.

## Хранение и интерфейсы (из раздела 6)

- База не меняется (v14). `SessionSummary.thumbPath` — путь, найденный хранилищем (`RoomSessionRepository` через `SessionAudioFiles.thumbOf`), а не поле базы. `VideoFiles.makeThumb` — новое правило на обеих платформах (Android — `MediaMetadataRetriever.getFrameAtTime`, iOS — `AVAssetImageGenerator`); моменты кадра, выбор светлого и имя миниатюры — общие (`VideoThumbs`). Отметка правила — `VideoThumbRuleStore` поверх того же файла настроек.
