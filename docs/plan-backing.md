# План: минусовка (spec 3.32, 5.25, этапы 85–89)

Спека — `docs/spec/backing.md`, черновик 0.67. Макет — `docs/design/project/backing/project/` (холст «Минусовка»).

## Решения владельца

- Видео под минусовку снимает своя камера на **CameraX** — новая зависимость согласована (2026-09-23).
- Минусовка через **динамик запрещена**: без наушников записи под минусовку нет.

## Решения, принятые без владельца

- **Скрипка пишется отдельно, сводится потом.** Сдвиг и громкость минусовки — свойства дубля, а не записи: их можно править на слух сколько угодно, оригинал не меняется (как обработка, 3.17).
- **Сдвиг — из системных часов, задержка беспроводных — из калибровки.** Отметки `AudioTrack` / `AudioRecord` точны для проводных и динамика; для Bluetooth многие телефоны их занижают, поэтому к ним прибавляется задержка, измеренная на самом человеке: он играет в такт щелчкам, и в число входит то, как он сам слышит и попадает.
- **Калибровка — не настройка**, а лист в потоке записи (правило CLAUDE.md: прочих настроек не делаем). Вход — перед первой записью с незнакомыми беспроводными и строка в блоке минусовки.
- **«Запомнить для …»**: правка сдвига у дубля может уточнить задержку наушников — так калибровка улучшается сама.
- **Звук видео под минусовку пишет наш конвейер, камера — только картинку.** Один способ считать сдвиг для обоих видов дублей; разбор готов сразу; микрофон не делят CameraX и `AudioRecord`.
- **Видоискатель — `camera-compose` (`CameraXViewfinder`)**, а не `PreviewView`: экран остаётся на Compose без View-интеропа. Если на выбранной версии CameraX его нет в стабильной ветке — `PreviewView` в `AndroidView` только на экране съёмки (записать в заметки).
- **Копии минусовок не дублируются**: одна копия файла на все ссылки (произведение и дубли), удаляется, когда ссылок нет.
- **Системная камера остаётся** для «Снять видео» без минусовки: своя камера появляется только там, где без неё нельзя.

## Этапы

85. **Домен и хранение.**
    - `core/domain/backing/`: `Backing` (файл, название, длительность, частота, каналы), `BackingConfig` (пределы, громкость по умолчанию, диапазоны сдвига и громкости, калибровка: темп, щелчки, окно, пороги годности), `BackingOffset` (сдвиг из двух отметок времени и задержки выхода; выход — проводные / USB / беспроводные / динамик — из типа `AudioDeviceInfo`, чистым перечислением), `Calibration` (щелчки по часам выхода, начала нот → попадания, медиана, межквартильный размах, годность), `HeadphoneLatencies` (имя → мс, до 20, по последнему использованию) с `HeadphoneLatencyCodec`, `BackingRepository`, `BackingFiles`.
    - `core/data/backing/`: `BackingEntity`, `BackingDao`, `RoomBackingRepository`; `PieceEntity.backingId`, у сессии — `backingId`, `backingOffsetMs`, `backingGainDb`, `backingPlayedMs`, `backingOutput`; миграция на следующую версию базы и схема; сборщик файлов без ссылок (при старте, рядом с `ShareSweep`).
    - `core/audio/backing/`: `BackingImporter` (проверка через `MediaExtractor`, место, копия без перекодирования), `BackingDecoder` (PCM стерео float), `Resampler` (окно Ланцоша, как в `LagSearch`) — чистое ядро с тестами на синтетике (`SignalSynth`).
    - DataStore: `headphone_latency`. Копия данных (3.20): папка `backings` в архиве; тест восстановления.
    - Тесты: `BackingOffsetTest`, `CalibrationTest` (ровно в такт, разброс, пропуски, ранние и поздние удары, вступление не считается), `HeadphoneLatencyCodecTest`, `ResamplerTest` (44.1 → 48 и обратно: частота тона, уровень, без щелчков на стыках блоков), `BackingImporterTest` (на JVM — через фейковый экстрактор), миграция (инструментальный, с предыдущей версии: всё цело, минусовок нет), сборщик файлов.

86. **Сведение и слушание.**
    - `core/audio/playback`: `ChainSessionPlayer` получает вторую дорожку: скрипка → `SoundChain` → центр; минусовка → громкость → сдвиг (кроссфейд 30 мс при правке на ходу) → сумма → ограничитель. Выход плеера — стерео.
    - Экран записи: переключатель «с минусовкой / только скрипка». Экран «Звук»: блок «Минусовка» (громкость, сдвиг, «−5 / +5», «Как записано», «Запомнить для …»).
    - «Поделиться»: вариант «С минусовкой» — `SoundFileRenderer` пишет стерео 192 кбит/с; у видео-дубля — та же дорожка в `.mp4` рядом с исходной картинкой.
    - Строки — русский и ещё девять по `docs/i18n-glossary.md` (добавить «минусовка», «сдвиг», «задержка наушников»).
    - Тесты: сведение (сдвиг вперёд и назад, срез начала, тишина до, громкость, ограничитель, скрипка без минусовки бит в бит равна прежней цепочке), рендер файла стерео, редьюсер экрана «Звук».

87. **Запись под минусовку.**
    - Экран произведения: блок «Минусовка» (добавить — системный выбор файла, прослушивание, «Заменить», «Убрать» с вопросом), чип «С минусовкой», запрет без наушников, строка «Наушники · … · 212 мс · Проверить».
    - `TakePipeline`: старт минусовки вместе с записью (`AudioTrack` в режиме низкой задержки, отметки времени обоих концов), полоса хода, отключение наушников (`AudioDeviceCallback`) — минусовка стоп, запись дальше; в сессию пишутся сдвиг, выход и `backingPlayedMs`.
    - Лист «Настроим наушники»: щелчки, восемь точек, итог, «Ещё раз»; микрофон только на время калибровки; не занятие.
    - Карточка дубля: значок минусовки.
    - Тесты: редьюсер блока и чипа (нет наушников, беспроводные без задержки → лист), `TakePipeline` на фейковом выходе (сдвиг записан, отключение наушников), редьюсер калибровки.

88. **Своя камера.**
    - `libs.versions.toml`: CameraX (`camera-core`, `camera-camera2`, `camera-lifecycle`, `camera-video`, `camera-compose`) — последняя стабильная версия на момент этапа. Манифест: `CAMERA`, `uses-feature camera required=false`.
    - `feature/camera/`: `CaptureScreen` (видоискатель, камеры, кнопка, таймер, полоса минусовки, касание — фокус, поворот без остановки), `CaptureViewModel`, разрешение (тот же помощник, что у микрофона).
    - Картинка — `VideoCapture` без звука во временный файл; звук — конвейер дубля; склейка `MediaMuxer` по `CLOCK_MONOTONIC` (`VideoMuxer`, чистое вычисление сдвига дорожек — с тестом), затем обычный путь видео-дубля (3.19) с готовым разбором.
    - Меню «Видео-дубль»: «Снять под минусовку».
    - Тесты: вычисление сдвига склейки, редьюсер экрана съёмки (нет разрешения, нет наушников, мало места), меню.

89. **Проверка.**
    - Эмулятор (`-PfakePitch=true` там, где звук не нужен): блок минусовки, импорт mp3 / m4a / wav, отказ на битом файле, чип и запрет без наушников (эмулятор — без наушников), экран «Звук», сведение на слух через динамик компьютера, «Поделиться» стерео. Камера эмулятора — виртуальная сцена: экран съёмки и склейка.
    - Телефон владельца — **только `adb install -r` и только с его согласия**: беспроводные и проводные наушники, калибровка, совпадение на слух, склейка видео, отключение наушников посреди дубля.
    - Спека «как сделано», заметки `docs/notes/backing.md`, строка в таблице `CLAUDE.md`, хроника.

Коммит на этап; каждый собирается и проходит `testDebugUnitTest` сам по себе.

## Как сделано (итог этапов 85–89)

Все пять этапов сделаны, по коммиту на этап плюс две правки после проверки. Отклонения от плана:

- **Хранение — три таблицы, а не колонки** у произведения и сессии: `backings`, `piece_backings` (минусовка произведения и чип), `take_backings` (всё о дубле, в том числе `recordedOffsetMs` для «Как записано» и `latencyMs`, с которой записан, — для «Запомнить для …»). База v13.
- **Разрешения камеры** спрашиваются на самом экране съёмки (камера и микрофон вместе), отказ — там же поверх видоискателя, а не в меню «Видео-дубль».
- **Выбор камеры не запоминается между входами** — только пока открыт экран; каждый вход — задняя. Перенесено в раздел 7.
- **Пометки «картинка может расходиться со звуком» нет**: без телефона не проверить, как распознать чужие часы кадров. Начало картинки — `System.nanoTime()` в событии `Start`; перенесено в раздел 7 вместе со сдвигом картинки на слух.
- **Поворот не останавливает съёмку** — это потребовало persistent recording CameraX (experimental API, opt-in в одном месте): активность пересоздаётся при повороте.
- **«Назад» во время съёмки** останавливает и сохраняет дубль — в спеке этого не было, добавлено.
- **Конец минусовки**: потоковый `AudioTrack` не доигрывал последний буфер — теперь его останавливают после последней записи и ждут доигрывания.
- **Сборка `-PfakePitch=true`** притворяется, что подключены беспроводные наушники (`FakeHeadphoneRoutes`), иначе на эмуляторе нечего показать; видео под минусовку в ней не склеивается — у фейкового источника нет звука.
- **Видоискатель** — `CameraXViewfinder` из `camera-compose` 1.6.2, запасной вариант с `PreviewView` не понадобился.

Проверка — в шапке `docs/notes/backing.md`: на эмуляторе всё, что он умеет; телефон владельца не трогали — ждёт его согласия.

## После проверки владельцем (0.69)

Владелец попробовал на телефоне: лист «Настроим наушники» прыгал, а сдвига ±500 мс не хватило, чтобы скрипка встала хотя бы чуть раньше минусовки. Решение владельца — калибровку убрать, оставить ползунок. Сделано:

- калибровки щелчками нет совсем (лист, щелчки, распознавание начал нот, вопрос перед первым дублем; `Calibration`, `OnsetDetector`, `HeadphoneCalibration.kt` и их тесты удалены);
- на экране произведения под строкой наушников — ползунок «Задержка наушников» 0…1000 мс (тот же `ParamSlider`, что на «Звуке»), число пишется для этих наушников через 400 мс после остановки пальца;
- сдвиг дубля на «Звуке» — ±1000 мс; «Запомнить для …» — у любых наушников, не только беспроводных, и правит то же число;
- на «Звуке» переключатель «с минусовкой / только скрипка» в портрете лежал поверх плеера (оба в одном `Box`) — теперь под ним.

## Риски

- **Отметки времени Bluetooth.** Если на Pixel 10a `AudioTrack.getTimestamp` для беспроводных уже включает задержку, калибровка покажет около нуля — это правильный результат, а не ошибка; число по умолчанию (200 мс) тогда надо будет уменьшить.
- **Часы кадров CameraX.** Время кадров обычно на `CLOCK_MONOTONIC`, но на части устройств — на своих часах сенсора; тогда склейка разойдётся, и дубль получит пометку (5.25). Проверяется только на телефоне.
- **Размер копии данных** вырастет на размер минусовок (обычно 5–10 МБ на произведение).
